## 3. 事实 vs 假设（总原则）

### 3.1 已锁定事实（样本中按「事实」表述）

- 本系统为**管理汇聚中枢**：消费**既有** IoT / 边缘 AI 的识别结果（数量、成熟度、菌盖直径、病害、抓拍、环境参数等）。
- **本应用不建设、不交付计算机视觉 / 识别算法**；识别在棚端 AI 盒或既有边缘侧完成。
- 需求覆盖九个方向：MQTT/HTTP 接入；看板/大屏；告警阈值 + 三级 + 闭环 + 推送；生长趋势；病害溯源；采摘清单 + 近 2–3 日产量预估；Excel 报表；约 110 路摄像头 + AI 盒 + 传感器档案；RBAC（四角色、棚隔离、审计）。
- UI：偏公安/雪亮风格的**暗色科技指挥大屏**（棚区平面示意即可，**不承诺真三维**）；**可售卖级 UI 为硬约束**。
- **MVP 优先**（接入 + 告警 + 采摘/报表 + 设备/权限）；二期再增强大屏/趋势/产量预估等。
- 硬风险：协议冻结、数据质量、告警噪音、产量预估依赖历史、图片存储。
- 市场定位：环控平台 + 监控指挥大屏 + AI 结果汇聚（相对缺少 AI 数菇/抓拍墙产品化呈现）。

### 3.2 【假设】默认值（已写入全文，可日后调整）

- 技术栈：**NestJS + Vue3/TS/Vite/Tailwind 暗色定制 + ECharts + PostgreSQL/Redis/MinIO/Mosquitto**。  
- 规模：**30 棚**、约 **110** 路摄像头、约 **30** 台 AI 盒；**On-Prem 私有化**。  
- 角色：系统超管 / 生产管理员 / 棚区负责人 / 只读查看员。  
- 告警：提示/一般/严重 + 文内默认阈值表；MVP 推送 = 站内 + 浏览器通知。  
- 保留：抓拍热数据 **90** 天；识别明细 **180** 天；日聚合长期；审计 ≥1 年。  
- 凡标 **【假设】** 的条款，法律/合同层面仍建议在盖章前由甲方确认；**样本文本本身已可直接当技术附件使用**。
