# 智慧食用菌棚 IoT+AI 管理平台 — 招标技术规格书（草稿）

> **文档性质**：招标技术附件草稿，可直接作为发标技术规格基础文本。  
> **标注说明**：文中 **【假设】** 为样本已填入的默认参数（规模、阈值、保留期、技术栈、部署等）；甲方后续可改数，改前按本默认执行评审口径。  
> **不含**：投标人名称、报价、商务条款。  
> **建设定位**：管理汇聚中枢；**不包含**计算机视觉算法与边缘推理交付。

---

## 1. 项目名称与建设范围

### 1.1 项目名称

智慧食用菌栽培基地 IoT+AI 管理平台（软件）

### 1.2 建设目标

建设一套面向食用菌基地的 **环境与设备管理 + AI 识别结果汇聚 + 告警闭环 + 采摘与报表 + 农业监控指挥大屏** 软件平台，对接甲方既有摄像头、边缘 AI 盒与环境传感器，实现生产管理可视化与闭环处置。大屏以清亮农作物监控风格为主，暗色非必须；本项目不是公共安全视频监控，不得按公安 / 雪亮类系统验收。

### 1.3 范围内

- 平台软件设计、开发、部署、培训与质保期内缺陷修复。  
- MQTT / HTTP 双通道接入既有边缘侧识别结果与环境数据。  
- 管理端、指挥大屏（清亮农作物监控风格为主，暗色非必须）、权限与审计、Excel 报表。  
- 与既有 IoT/边缘 AI 的接口联调（以甲方/边缘方提供的冻结样例为准）。

### 1.4 范围外（明确不做）

- 摄像头、AI 推理盒、传感器等**硬件采购与安装**。  
- **识别算法 / 模型训练 / 边缘推理软件**（由既有边缘系统完成）。  
- 真三维数字孪生、倾斜摄影、BIM。  
- ERP、财务、销售电商、人事考勤。

### 1.5 规模参数（【假设】已填默认）

| 项 | 默认值 |
|----|--------|
| 基地 | 1 个 |
| 栽培棚 | **30 棚** |
| 摄像头 | **约 110 路** |
| 边缘 AI 盒 | **约 30 台**（按棚 1 台计量，实际以档案为准） |
| 环境测点 | 每棚温湿度、CO₂、基质含水率（由既有 IoT 上报） |
| 用户并发 | 管理端 ≤30；大屏常开 1–3 路 |
| 界面语言 / 时区 | 简体中文 / Asia/Shanghai |

## 2. 总体技术要求

### 2.1 架构原则

- 平台为**汇聚与管理中枢**：只消费边缘已产出的结构化结果与抓拍，不在平台内做视觉推理。  
- 接入、存储、告警、展示分层；关键配置可审计。  
- 支持私有化部署与内网运行。

### 2.2 推荐技术栈（【假设】）

| 层次 | 要求 |
|------|------|
| 后端 | NestJS（TypeScript）或同等可维护的现代后端框架；若投标人替换，须在投标文件说明等价能力 |
| 前端 | Vue 3 + TypeScript + Vite；UI 为**清亮农作物监控风格**（允许 Tailwind 或同等工程化方案；暗色非必须）。须交付可投屏的农业监控大屏，不得只交未完成大屏的口头承诺；也不得按公安 / 雪亮类系统验收 |
| 图表 | ECharts 或同等 |
| 数据库 | PostgreSQL |
| 缓存 | Redis |
| 对象存储 | MinIO 或兼容 S3 的私有化对象存储（抓拍） |
| MQTT | Mosquitto 或同等 Broker |
| 部署 | Docker Compose 一键依赖；**【假设】客户机房 / 基地 On-Prem 私有化** |

> 栈为推荐假设。投标人可采用等价方案，但须满足全部功能、性能、安全与 UI 约束，并在投标技术偏离表中列明。

### 2.3 部署与运行环境（【假设】）

- 部署形态：**本地私有化（On-Prem）**。  
- 服务器：**【假设】**应用 + 中间件共 1～2 台 x86 服务器（16C/64GB/系统盘 + 数据盘 ≥4TB 起，可按保留策略扩容）。  
- 浏览器：Chrome / Edge 近两个大版本；大屏分辨率 **1920×1080** 及以上。  
- 备份：数据库每日备份；对象存储生命周期按保留策略执行。

## 3. 功能要求（必须 / 可选）

图例：**M** = 必须（MVP/一期）；**O** = 可选或二期（可列入招标可选包）。

### 3.1 数据接入（M）

1. 支持 **MQTT + HTTP** 双通道接收识别与环境数据。  
2. 具备报文校验、去重、异常过滤；支持断网补传且幂等。  
3. 抓拍图存储于对象存储，按 **棚 / 日期 / 摄像头** 归档，管理端可检索预览。  
4. 拒收非法报文须留日志（时间、设备、原因）。

**上报字段（最低集，【假设】命名可与样例 JSON 对齐）**

| 字段 | 说明 |
|------|------|
| shedId | 棚区编号 |
| cameraId | 摄像头编号 |
| recognizedAt | 识别时间 |
| mushroomCount | 蘑菇数量 |
| matureCount | 成熟数量 |
| capDiameters | 菌盖直径（列表或统计） |
| diseaseCount / diseaseLevel | 病害数量 / 等级 |
| snapshot | 抓拍图（URL 或上传二进制） |
| temperature / humidity / co2 / substrateMoisture | 环境参数 |

### 3.2 管理看板与指挥大屏（M + O）

| 要求 | 级别 |
|------|------|
| 管理端基地/棚汇总：数量、成熟、病害、设备在线、未关闭告警 | M |
| 指挥大屏：总览、告警条、基础抓拍区、棚平面/拓扑示意（**不要求真 3D**；清亮农作物风格为主，暗色非必须） | M |
| 精装抓拍墙、多布局大屏、对比时间轴 | O（二期） |

UI 硬约束见第 7 章及附件 `05-界面与交付说明.md`。

### 3.3 告警（M；外部推送 O）

1. 阈值可配置；支持类型：成熟、病害、生长停滞、环境越限、设备离线。  
2. 告警级别三档：**提示 / 一般 / 严重**。  
3. 闭环：产生 → 通知 → 确认/认领 → 处置备注 → 关闭或误报标记；全过程可查。  
4. MVP 推送：**站内消息 + 浏览器通知**（【假设】）。  
5. **企微 / 钉钉**推送为可选（O）。

**【假设】默认阈值**（上线可调，验收以可配置为准）：

| 类型 | 提示 | 一般 | 严重 |
|------|------|------|------|
| 成熟占比 | ≥40% | ≥60% | ≥80% |
| 病害个数 | ≥1 | ≥3 | ≥5 或高等级 |
| 温度偏离棚设定 | ±1℃ | ±2℃ | ±3℃ |
| 湿度偏离棚设定 | ±5%RH | ±10% | ±15% |
| CO₂ 超上限比例 | 10% | 20% | 30% |
| 设备离线 | 2 个心跳周期 | 5 个周期 | ≥15 分钟 |
| 生长停滞 | — | 连续 48h 直径无增长 | 连续 72h |

**【假设】棚环境设定中心默认**：温度 18℃、湿度 85%RH、CO₂ 上限 1200ppm。

须提供抑制噪音手段：静默期、同类合并或死区（实现方式不限，验收可演示降噪效果）。

### 3.4 采摘与台账（M）

- 当日可采统计、每日采摘清单（支持人工修正备注）。  
- 清单可按棚/日期筛选。

### 3.5 报表（M）

至少提供 Excel（xlsx）导出：生长类、病害类、环境类、设备类、告警类。筛选条件与导出字段一致。

### 3.6 生长趋势 / 病害溯源 / 产量预估

| 要求 | 级别 |
|------|------|
| 病害记录列表（含抓拍关联） | M |
| 生长趋势曲线、抓拍对比时间轴 | O |
| 病害与环境联动溯源 | O |
| 近 2–3 日产量预估（须标注「估计」；**【假设】满 30 天有效历史后启用预估验收**） | O |

### 3.7 设备管理（M）

- 摄像头（约 110 路）、AI 盒、传感器档案：增删改查、棚绑定、批量导入、在线状态。  
- 离线触发告警（规则见 3.3）。

### 3.8 权限与审计（M）

**【假设】四角色**：

| 角色 | 权限概要 |
|------|----------|
| 系统超管 | 全功能、用户与角色、系统配置 |
| 生产管理员 | 多棚业务、阈值、报表、告警处置 |
| 棚区负责人 | 仅授权棚的查看与告警处置、采摘 |
| 只读查看员 | 授权棚只读 |

- 强制**棚级数据隔离**。  
- 登录（成功/失败）与关键操作（用户、阈值、处置、导出等）审计可查。

## 4. 数据保留与容量（【假设】）

| 数据类型 | 默认保留 |
|----------|----------|
| 抓拍图（在线热数据） | **90 天** |
| 识别原始明细 | **180 天** |
| 日聚合统计 | **长期保留（≥3 年）** |
| 告警与审计日志 | **≥1 年** |

超期策略：删除或转冷存由实施方案写明；投标须给出按 110 路、30 棚估算的存储容量建议。

## 5. 接口与联调要求（对既有 IoT / 边缘 AI）

### 5.1 甲方 / 边缘方须提供（发标或澄清阶段）

1. MQTT：Broker 地址策略、Topic 树、QoS、鉴权方式、样例报文（≥3 种：正常识别、病害、环境）。  
2. HTTP：Path、Method、鉴权、请求/响应样例、补传约定。  
3. 抓拍：URL 拉取或二进制上传约定、图片格式（【假设】JPEG）、大小上限（【假设】单张 ≤2MB）。  
4. 设备编码规则：棚、摄像头、AI 盒 ID 唯一性说明。  
5. 时钟与时区约定（【假设】Asia/Shanghai）。

### 5.2 投标人须提供

1. 平台侧接入适配说明与**联调计划**。  
2. 基于甲方样例的**模拟接入工具或脚本**（用于无边缘环境演示）。  
3. 接口冻结后的变更影响评估流程。  
4. 安全：传输加密建议（内网 TLS）、设备/上报鉴权方案。

### 5.3 协议冻结

- 以签字确认的样例与 Schema 版本为验收依据。  
- 边缘侧单方变更导致联调失败的，不计入平台方延误（商务条款另述）。

## 7. 界面与体验硬约束

1. 指挥大屏须为可对外演示的农业监控界面，视觉为**清亮农作物监控风格**（暗色非必须），信息层级清晰，适合投屏。不得按公安 / 雪亮或公共安全指挥中心风格验收。  
2. **允许**棚区平面示意图或拓扑图；**不接受**以「未做 3D」为唯一交付物而缺少可用平面总览。  
3. **不要求**像素级复刻任何第三方产品界面；也**不得**抄袭第三方商标与受版权保护的视觉资产。  
4. 详细边界与演示范围见 `05-界面与交付说明.md`（建议作为本规格书附件）。

## 8. 分期交付与成果物

### 8.1 分期（【假设】）

| 阶段 | 内容 | 建议周期口径 |
|------|------|--------------|
| 一期 MVP | 接入、告警闭环、采摘与 Excel、设备档案、RBAC、管理端、大屏基础总览 | 以合同为准 |
| 二期 | 精装大屏/抓拍墙、趋势、病害环境联动、产量预估、企微/钉钉 | 以合同为准 |

### 8.2 交付物（必须）

1. 可部署软件包与源代码（范围按合同）。  
2. 部署手册、管理员手册、接口文档。  
3. 测试报告与验收记录。  
4. 培训（**【假设】现场或远程 ≥1 次，含管理员操作**）。  
5. 质保（**【假设】验收后 12 个月缺陷修复**，商务可调）。

## 9. 验收要点

### 9.1 一期（MVP）

1. 使用冻结样例或模拟器连续上报，管理端展示数量/成熟/病害/环境/抓拍正确。  
2. 至少 3 类告警可被规则触发，完成闭环与审计查询。  
3. 采摘清单与不少于 2 类 Excel 导出通过。  
4. 约 110 路设备档案可维护；四角色 + 棚隔离演示通过。  
5. 指挥大屏基础页 1080p 投屏演示通过（总览 + 告警 + 平面棚示意；清亮农作物监控风格为主，暗色非必须）。

### 9.2 二期（若采购）

1. 精装大屏/抓拍墙按脚本演示。  
2. 趋势与病害—环境联动可复盘。  
3. 产量预估在历史门槛满足后可用，并明示「估计」口径。  
4. 企微或钉钉严重告警推送成功（选一即可，除非合同双开）。

### 9.3 不通过情形（示例）

- 平台内夹带「现场训练视觉模型」却无法稳定接入既有边缘结果。  
- 仅提供默认组件库后台、无可投屏的农业监控大屏。  
- 无棚隔离或无审计。  
- 无法按样例完成 MQTT 或 HTTP 任一主通道接入（双通道均为必须能力）。
