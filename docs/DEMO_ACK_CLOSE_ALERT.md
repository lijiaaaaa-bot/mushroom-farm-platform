# 确认或关闭一条待确认告警

先有一条待确认的温度过高告警。数据库和前后端已经在跑就跳过前三步。

```bash
make up && make migrate
make api
make web
make demo-one-alert
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。`make demo-one-alert` 留下棚区 S01、摄像头 CAM-ALERT-01 的「温度过高告警」，状态是待确认。这条命令本身不改。

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。棚区负责人 `shedlead` / `Shed@123456` 也可以确认和关闭自己棚里的告警。查看账号没有这两个按钮。

## 在列表里确认

打开 http://127.0.0.1:43123/alerts 。状态筛选保持「全部」。

列表里有一条标题「温度过高告警」，状态列是「待确认」。点这一行的「确认」。

状态列变成「已确认」。「确认」按钮消失，「关闭」还在。上方「处置备注」默认是「已确认」，这次确认会带上这个备注。

刷新 http://127.0.0.1:43123/alerts 。这一条仍是「已确认」。把状态筛选改成「已确认」，这一条还在；改成「待确认」，这一条不在。

## 在列表里关闭

仍在这一条上点「关闭」。状态列变成「已关闭」，原因列是「正常关闭」。「确认」和「关闭」都消失。列表上的关闭也带上「处置备注」，默认仍是「已确认」，所以关闭备注显示「已确认」。

刷新 http://127.0.0.1:43123/alerts 。这一条仍是「已关闭」。状态筛选改成「已关闭」时看得到，改成「待确认」或「已确认」时看不到。

## 在详情里确认或关闭

从列表点标题「温度过高告警」，打开 http://127.0.0.1:43123/alerts/<告警 id> 。

待确认时有「确认」和「关闭」。点「确认」后，页面重新读取这一条：状态是「已确认」，确认备注是「已确认」。点「关闭」后，状态是「已关闭」，关闭原因是「正常关闭」，关闭备注是「已关闭」。

刷新这个详情地址，状态、备注和关闭原因仍是刚才写入的内容。已关闭后这两个按钮不再出现。

## 用命令再读一次

在仓库根目录，确认当前这条待确认告警：

```bash
make demo-ack-one-alert
```

命令找到棚区 S01、摄像头 CAM-ALERT-01 上状态为待确认的温度过高告警，`POST /api/v1/alerts/:id/ack`，备注「已确认」。然后重新 `GET /api/v1/alerts/:id`，并核对 `status=acked` 的列表里有这一条、`status=open` 的列表里没有。终端打印 `刷新后状态: 已确认`。

已经是已确认、没有待确认的一条时，命令失败，不改这条告警。先关闭，再执行 `make demo-one-alert`，才会再有待确认的一条。

关闭当前未闭合的这一条：

```bash
make demo-close-one-alert
```

待确认或已确认都可以关。`POST /api/v1/alerts/:id/close`，备注「已关闭」，关闭原因是正常关闭。然后重新读详情，并核对 `status=closed` 的列表里有这一条，待确认和已确认的列表里没有。终端打印 `刷新后状态: 已关闭`。

没有未闭合的温度过高告警时，这两个命令会先按 `make demo-one-alert` 的方式补一条识别，再确认或关闭。样例文件里的 `CAM-DEMO-01` 和温度 22.5 不改。

关闭之后再执行 `make demo-one-alert`，会新建一条，因为未闭合的那条已经没了。只确认、不关闭时，再执行 `make demo-one-alert` 仍沿用这一条。
