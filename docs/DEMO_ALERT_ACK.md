# 告警列表确认并关闭

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录执行：

```bash
make demo-alert-ack
```

命令用管理员账号调用已有的告警接口。不发识别，不改阈值，也不改 `make demo-one-alert` 留下的温度过高告警。`make demo-ack-one-alert`、`make demo-close-one-alert`、`make demo-alert-status-filter` 不改。

1. 棚区 S01、摄像头 `CAM-ACK-01`，标题「待确认操作告警」。已有同标题的待确认告警则沿用，否则 `POST /api/v1/alerts` 新建。这条保持待确认，命令不确认、不关闭。
2. 棚区 S01、摄像头 `CAM-ACK-02`，标题「已确认操作告警」。已有同标题且确认备注是「已确认」的已确认告警则沿用。只有待确认时，`POST /api/v1/alerts/:id/ack`，备注「已确认」，与 `make demo-ack-one-alert` 相同。都没有则先新建再确认。确认之后不再关闭。
3. 棚区 S01、摄像头 `CAM-ACK-03`，标题「已关闭操作告警」。已有同标题、确认备注「已确认」、关闭备注「已关闭」、关闭原因正常关闭的告警则沿用。只有待确认时，先确认再 `POST /api/v1/alerts/:id/close`，关闭备注「已关闭」。已经是已确认且确认备注相符时，只关闭。从待确认直接关掉时，确认备注会变成「关闭时自动确认」，那种不算这一条，命令会另走先确认再关闭。
4. 再读三次详情。待确认仍是待确认。已确认的 `ackNote` 是「已确认」，没有关闭原因。已关闭的状态是 `closed`，`ackNote` 仍是「已确认」，`closeNote` 是「已关闭」，`closeReason` 是 `resolved`。

终端打印三条 id，以及一句「走查: 待确认 → 已确认 → 已关闭」。

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

打开 http://127.0.0.1:43123/alerts 。状态下拉保持「全部」，不要改成待确认、已确认或已关闭。

列表里能看到这三行（新建的在较前）：

- 「待确认操作告警」，摄像头 `CAM-ACK-01`，状态「待确认」。这一行有「确认」和「关闭」。
- 「已确认操作告警」，摄像头 `CAM-ACK-02`，状态「已确认」。没有「确认」，还有「关闭」。
- 「已关闭操作告警」，摄像头 `CAM-ACK-03`，状态「已关闭」，原因「正常关闭」，标题下写着关闭备注「已关闭」。没有「确认」和「关闭」。

先截这三行，状态和按钮一起在画面里。

再在「待确认操作告警」这一行上操作。上方「处理说明」保持默认「已确认」，不要改成别的句子，也不要点进详情。

点这一行的「确认」。状态列变成「已确认」。「确认」消失，「关闭」还在。

再点同一行的「关闭」。状态列变成「已关闭」，原因列是「正常关闭」。因为处理说明仍是「已确认」，标题下的关闭备注是「已确认」。「确认」和「关闭」都消失。

刷新 http://127.0.0.1:43123/alerts 。这一行仍是「已关闭」。

`CAM-ACK-02` 那一行可以留着，用来对照「只确认、还没关」；不要为了截图去关它。认领和误报关闭不是这一条命令要看的按钮。
