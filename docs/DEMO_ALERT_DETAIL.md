# 打开一条告警的详情

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。API 启动时会写入种子规则「温度过高」：指标温度过高，阈值 28，级别严重。

在仓库根目录执行：

```bash
make demo-alert-detail
```

命令按 `make demo-one-alert` 的方式播种：读取 `packages/contracts/fixtures/recognition.demo-one.json`，把本次请求的摄像头编号改成 `CAM-ALERT-01`，温度改成 30，只 POST 一次识别。样例文件里的 `CAM-DEMO-01` 和温度 22.5 不改。30 高于阈值 28，留下一条未闭合的「温度过高告警」。同一摄像头已经有未闭合的温度过高告警时不再新建，终端打印 `告警: 沿用未闭合`。

然后读 `GET /api/v1/alerts/:id`。缺标题、说明、级别、状态、棚区、摄像头、发生时间、指标、当前值或阈值时，命令失败。

终端打印 `告警详情:`，地址形如：

http://127.0.0.1:43123/alerts/<告警 id>

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。然后直接打开终端里的这个地址。顶栏是「告警详情」。

这一页要能读到这些字段：

| 标签 | 值 |
|------|------|
| 标题 | 温度过高告警 |
| 说明 | 棚区 S01 摄像头 CAM-ALERT-01 温度过高 30，阈值 28 |
| 级别 | 严重 |
| 状态 | 待确认。沿用的若已确认，则是已确认 |
| 棚区 | S01 |
| 摄像头 | CAM-ALERT-01 |
| 发生时间 | 上海时间 |
| 指标 | 温度过高 |
| 当前值 | 30℃。沿用已有告警时，以终端打印的当前值为准 |
| 阈值 | 28℃ |
| 认领人 | — |
| 认领时间 | — |
| 确认人 | —。已确认时是确认的账号 |
| 确认时间 | —。已确认时是上海时间 |
| 关闭原因 | — |
| 关闭人 | — |
| 关闭时间 | — |

截图对着这一页。地址是 `/alerts/<告警 id>`，不是告警列表。

没有传感器时不出现「传感器」一行。有抓拍对象键时，图、对象键和「打开抓拍」也在这一页。这条命令不要求 MinIO，没有图也可以。

点「返回告警列表」回到 `/alerts`。本命令不确认、不关闭，也不改列表上的筛选。

`make demo-one-alert`、`make demo-ack-one-alert`、`make demo-close-one-alert`、`make demo-alert-ack` 都不改。样例文件里的 `CAM-DEMO-01` 不改。
