# 阈值规则可查可见

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录：

```bash
make demo-alert-rules
```

命令用管理员账号调用已有的阈值规则接口。账号 `admin`，密码 `Admin@123456`。

1. 读取 `GET /api/v1/alert-rules`。种子规则「温度过高」必须仍是指标温度过高、阈值 28、已启用。没有这条时命令失败，不会去新建它，也不会改它。
2. 没有名为「演示规则列表」的规则时，`POST /api/v1/alert-rules` 新建一条：指标湿度过高，阈值 95，级别提示，棚区 S01，窗口 360 分钟，启用。
3. 已有这条、且指标和棚区一致时，若阈值、级别、窗口或启用对不上，只 `PATCH` 这一条，写成阈值 95、级别提示、窗口 360 分钟、启用。指标或棚区对不上时命令失败，不另建一行。
4. `GET /api/v1/alert-rules/:id` 与列表里的这一行一致：名称、指标、棚区、阈值、等级、窗口分钟、启用。
5. 再读一次列表。其他规则的行数不变。种子规则「温度过高」仍是 28。

不发识别，不发环境，不发心跳。不确认、不关闭告警。不改「演示环境温度过高」「演示二氧化碳过高」和其他规则。

终端打印这两行地址：

```text
阈值规则列表: http://127.0.0.1:43123/alert-rules?ruleId=<id>
阈值规则详情: http://127.0.0.1:43123/alert-rules/<id>
```

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

## 1. 列表有行

打开终端里的「阈值规则列表」。侧栏是「阈值规则」。表里至少有描边的这一行：

| 名称 | 指标 | 棚区 | 阈值 | 等级 | 窗口分钟 | 启用 |
| --- | --- | --- | --- | --- | --- | --- |
| 演示规则列表 | 湿度过高 | S01 | 95 | 提示 | 360 | 是 |

管理员看到的阈值、等级、窗口是输入框，框里的数字和选项是上表。启用列写「是」。这一行有「打开」。

种子行「温度过高」若已在表里，指标是温度过高，阈值是 28，棚区是「全场」。没有棚区的规则都写「全场」。

没有「演示规则列表」这一行，或整页写成「暂无阈值规则。」，都算没对上。

## 2. 详情能展开字段

点这一行的「打开」，或直接打开终端里的「阈值规则详情」。顶栏是「阈值规则详情」。这一页要能读到：

| 标签 | 值 |
| --- | --- |
| 名称 | 演示规则列表 |
| 指标 | 湿度过高 |
| 棚区 | S01 |
| 阈值 | 95 |
| 等级 | 提示 |
| 窗口分钟 | 360 |
| 启用 | 是 |

点「返回阈值规则」回到列表，这一行仍被描出。

- 列表截图里至少有一行「演示规则列表」，能读到指标、棚区、阈值、等级、窗口分钟、启用。
- 详情截图里上述字段都在。
- 种子规则「温度过高」仍是 28。
