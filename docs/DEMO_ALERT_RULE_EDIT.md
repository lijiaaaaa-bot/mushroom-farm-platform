# 阈值规则可新建、可编辑

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录：

```bash
make demo-alert-rule-edit
```

命令用管理员账号调用已有的阈值规则接口。账号 `admin`，密码 `Admin@123456`。

1. 读取 `GET /api/v1/alert-rules`。种子规则「温度过高」必须仍是指标温度过高、阈值 28、已启用。没有这条时命令失败，不会去新建它，也不会改它。
2. 没有名为「演示规则新建」的规则时，`POST /api/v1/alert-rules` 新建一条：指标湿度过低，阈值 40，级别提示，不填棚区（全场），窗口 180 分钟。新建后启用。
3. 已有这条、且指标是湿度过低、棚区是全场时，不另建一行。若阈值、级别、窗口或启用还不是改前这组数，先 `PATCH` 写成阈值 40、级别提示、窗口 180 分钟、启用。指标或棚区对不上，或同名多于一条时，命令失败。
4. `GET /api/v1/alert-rules/:id` 与列表里的这一行都是改前：名称、指标、棚区全场、阈值 40、等级提示、窗口 180 分钟、启用。
5. 再 `PATCH` 这一条：阈值 55，级别一般，窗口 90 分钟，停用。
6. 再读详情和列表。两处都是改后：阈值 55、等级一般、窗口 90 分钟、启用否。名称、指标、棚区不变。
7. 其他规则的行数和字段不变。种子规则「温度过高」仍是 28。「演示规则列表」「演示环境温度过高」「演示二氧化碳过高」若已在表里，也不改。

不发识别，不发环境，不发心跳。不确认、不关闭告警。

终端打印改前和改后的对照，以及改完之后要打开的两个地址：

```text
对照: 阈值 40 → 55；等级 提示 → 一般；窗口分钟 180 → 90；启用 是 → 否
改后列表: http://127.0.0.1:43123/alert-rules?ruleId=<id>
改后详情: http://127.0.0.1:43123/alert-rules/<id>
```

命令结束时页面上是改后这组数。改前那一组留在终端，也留在下面的新建截图里。

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

## 1. 新建后列表有这一行

侧栏是「阈值规则」。上方有「新建规则」。名称填「演示规则新建」，指标选「湿度过低」，阈值填 40，等级选「提示」，窗口分钟填 180，点「新建规则」。

表单下写出「已新建「演示规则新建」。阈值 40，等级 提示，窗口分钟 180，启用 是。下方列表有这一行。」旁边有「打开详情」。表里这一行被描出：

| 名称 | 指标 | 棚区 | 阈值 | 等级 | 窗口分钟 | 启用 |
| --- | --- | --- | --- | --- | --- | --- |
| 演示规则新建 | 湿度过低 | 全场 | 40 | 提示 | 180 | 是 |

管理员看到的阈值、等级、窗口是输入框，框里是上表的数。启用列写「是」。这一行有「保存」「停用」「打开」。

库里已经有这条时，不要再点「新建规则」，否则会多出同名的一行，命令会失败。直接改下面这一行，或先跑命令，它会把已有的这一条写回改前再改成改后。

种子行「温度过高」若已在表里，指标是温度过高，阈值是 28。

截图：`docs/evidence/demo-alert-rule-edit/list-after-create.png`。画面里要能读到名称「演示规则新建」、指标湿度过低、棚区全场、阈值 40、等级提示、窗口 180、启用是。

## 2. 编辑后列表立刻是新值

在描出的这一行把阈值改成 55，等级改成「一般」，窗口分钟改成 90，点「保存」。再点「停用」。

保存后不用刷新整页。表单下改成「已保存「演示规则新建」。阈值 55，等级 一般，窗口分钟 90，启用 否。」输入框里是 55、一般、90。启用列写「否」，按钮变成「启用」。这一行仍被描出。

| 名称 | 指标 | 棚区 | 阈值 | 等级 | 窗口分钟 | 启用 |
| --- | --- | --- | --- | --- | --- | --- |
| 演示规则新建 | 湿度过低 | 全场 | 55 | 一般 | 90 | 否 |

对照就是：阈值 40 → 55，等级 提示 → 一般，窗口分钟 180 → 90，启用 是 → 否。名称、指标、棚区不动。

也可以只跑命令，然后打开终端里的「改后列表」。看到的是上面这张改后的表，不是改前。

截图：`docs/evidence/demo-alert-rule-edit/list-after-edit.png`。要能同时看出 55、一般、90、否，并和新建截图里的 40、提示、180、是对得上。

## 3. 详情立刻是同一组数

点「打开详情」，或点这一行的「打开」，或打开终端里的「改后详情」。顶栏是「阈值规则详情」。

| 标签 | 值 |
| --- | --- |
| 名称 | 演示规则新建 |
| 指标 | 湿度过低 |
| 棚区 | 全场 |
| 阈值 | 55 |
| 等级 | 一般 |
| 窗口分钟 | 90 |
| 启用 | 否 |

这组和列表上刚保存的一致。点「返回阈值规则」回到列表，这一行仍被描出，输入框仍是 55、一般、90，启用仍是「否」。

截图：`docs/evidence/demo-alert-rule-edit/detail-after-edit.png`。上述字段都在，并且是改后的值，不是 40、提示、180、是。

## 验收

- `make demo-alert-rule-edit` 在 API 已启动时退出码 0，并打印对照以及改后列表、改后详情两个地址。
- 新建截图里有一行「演示规则新建」，能读到湿度过低、全场、40、提示、180、是。
- 编辑后的列表截图里同一行是 55、一般、90、否。
- 详情截图里是同一组改后的值。
- 种子规则「温度过高」仍是 28。

`make demo-alert-rules`、`make demo-alert-rule-config`、`make demo-threshold-alert` 与 `make demo-telemetry-threshold-alert` 不改。不改接入观测。
