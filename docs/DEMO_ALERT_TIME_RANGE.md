# 按起止时间筛选告警

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录执行：

```bash
make demo-alert-time-range
```

命令用管理员账号调用告警接口。不发识别，不确认，不关闭。状态下拉保持「全部」，不改 `make demo-alert-status-filter`。

列表里的「时间」列是告警的 `createdAt`。`GET /api/v1/alerts` 用 `from`、`to` 按这个时刻比较，含两端。空白不传。开始晚于结束，或不是有效时间，接口返回 400，页面写「时间筛选无效」，不保留上一次的列表，也不写「暂无告警。」。没有落在窗口里的行时写「没有符合条件的告警。」。

`POST /api/v1/alerts` 可以带 `createdAt`，用来把这三条放到指定时刻。同一棚区、同一摄像头、同一标题已存在时，沿用该条并改 `createdAt`，不另建一行。页面上的「新建告警」不填这个字段。

1. 棚区 S01、摄像头 `CAM-TIME-01`，标题「时间窗外告警」。`createdAt` 是当前时刻前 3 小时。
2. 棚区 S01、摄像头 `CAM-TIME-02`，标题「时间窗内较早告警」。`createdAt` 是当前时刻前 8 分钟。
3. 棚区 S01、摄像头 `CAM-TIME-03`，标题「时间窗内当前告警」。`createdAt` 是当前时刻。
4. 宽窗口是当前时刻前 4 小时到后 1 分钟。`GET /api/v1/alerts?q=时间窗&from=…&to=…` 含这三条。每一条的 `createdAt` 都在窗口内。
5. 窄窗口是当前时刻前 30 分钟到后 1 分钟。同一查询只含第 2、3 步，不含第 1 步。窄窗口的 `total` 小于宽窗口。
6. 窄窗口再加 `status=open` 时，第 2、3 步仍在，第 1 步仍不在。状态下拉没有被起止时间换掉。
7. `GET /api/v1/alerts/:id` 能打开「时间窗内当前告警」，`createdAt` 仍是第 3 步的时刻。

终端打印三条告警的 id 和 `createdAt`，以及两个列表地址：宽窗口、窄窗口。两个地址都不带 `status`。标题关键词 `q=时间窗` 用来把这三条和别的告警分开，方便对截图。

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

## 截图

拍两张，都要登录后的告警列表，状态下拉是「全部」。

1. 打开终端打印的「宽窗口列表」。地址带 `q=时间窗` 以及 `from`、`to`，不带 `status`。页面有「开始时间」「结束时间」，并写出「时间 … 至 …」。表里同时有「时间窗外告警」「时间窗内较早告警」「时间窗内当前告警」。时间列能对上这三条的先后。
2. 打开终端打印的「窄窗口列表」。状态下拉仍是「全部」。表里有「时间窗内较早告警」和「时间窗内当前告警」，没有「时间窗外告警」。行数比第 1 张少。

也可以在 `/alerts` 自己填开始和结束，点「查询」。点「清除时间」后不再按起止时间过滤，状态下拉保持刚才的选择。地址栏直接打开终端打印的地址，效果与点「查询」相同。

把状态下拉改成「待确认」时，地址仍带着原来的 `from`、`to`。窗内待确认还在，窗外那条仍不在。改回「全部」后，起止时间还在。

`make demo-alert-ack`、`make demo-alert-status-filter`、`make demo-one-alert`、`make demo-duty-board` 不改。
