# 病害高发时段与棚区可查可见

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录：

```bash
make demo-disease-hotspot
```

命令读取 `packages/contracts/fixtures/recognition.demo-disease-hotspot.json`。样例文件不改。`recognition.demo-one.json` 里的 `CAM-DEMO-01` 不改。识别时间按运行时刻重算，数量以样例里的 `points` 为准：

| 角色 | 棚区 | 摄像头 | 时间 | 病害数量 |
| --- | --- | --- | --- | --- |
| 峰值 | S03 | `CAM-DH-A`、`CAM-DH-B`、`CAM-DH-C` | 当前小时 | 各 4，棚合计 12 |
| 对照小时 | S02 | `CAM-DH-LOW` | 当前时刻前 3 小时 | 1 |
| 对照日 | S03 | `CAM-DH-DAY` | 当前时刻前 2 日 | 1 |

同一小时再跑，幂等键 `demo-disease-hotspot-<摄像头>-<上海整点或上海日>` 已在则沿用，不另建一行，样本数不加。病害等级都是 1。蘑菇数量 12，成熟数量 4，温度 22.5℃，湿度 88%，CO₂ 900，基质含水率 70%。每条病害数量低于种子规则「病害数量一般」的 5，病害等级低于「病害等级一般」的 2，成熟占比低于「成熟占比一般」的 0.6，所以这五条不新开告警。对象存储没起来时，第一次写入失败。

然后读两份高发统计，都不带 `shedCode`：

- `GET /api/v1/diseases/peaks?grain=hour` 读近 24 小时的小时桶。当前小时的病害数量不少于 12，前 3 小时那一桶不少于 1，并且当前小时更高。棚区 S03 不少于 12，S02 不少于 1，S03 高于 S02。`peak` 是时段表里病害数量最大的那一行。
- `GET /api/v1/diseases/peaks?grain=day` 读近 7 日的日桶。当天（若前 3 小时跨过上海零点，则是当前小时所在的那一天）高于 2 日前那一天。S03 仍高于 S02。两日前那一条在小时窗口外，小时表里看不到它。

棚合计是该窗口内各小时或各日、各摄像头最新病害数相加。窗口里若还有别的摄像头写过病害，对应棚的合计会更大。本命令写入的 S03 仍高于 S02，当前小时仍高于前 3 小时。

终端打印这两行地址：

```text
小时: http://127.0.0.1:43123/diseases?grain=hour
日: http://127.0.0.1:43123/diseases?grain=day
```

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。侧栏「病害」也进这一页。

## 1. 小时

打开终端里的「小时」。页顶是「病害高发」，「小时」按钮是当前选中。窗口文字是「近 24 小时」。同一屏有两张表：

| 表 | 要能读到 |
| --- | --- |
| 高发时段 | 至少两行。病害数量更大的那一行标着「峰值」，条更长 |
| 高发棚区 | S03 和 S02 都在。S03 的病害数量大于 S02，更大的那一行标着「最高」 |

干净库里，峰值时段的病害数量是 12，S03 是 12，S02 是 1。页顶还有一行「峰值时段 … · 病害数量 … · 最高棚区 …」。下面的病害记录仍是识别明细，能看到这几台摄像头。

没有这两张表，或两行病害数量一样、看不出哪一段更高，都算没对上。

## 2. 日

打开终端里的「日」，或在同一页点「日」。窗口文字变成「近 7 日」。时段列只写到日期，不写到分钟。「小时」不再是当前选中。

高发时段里，较近的那一天高于 2 日前。高发棚区里 S03 仍高于 S02。干净库、并且当前小时和前 3 小时在同一个上海日时：当天这一行的病害数量是 13（S03 的 12 加上 S02 的 1），2 日前是 1；棚区 S03 是 13，S02 是 1。若前 3 小时跨过上海零点，当天这一行是 12，S02 的 1 落在前一天，2 日前仍是 1；棚区 S03 仍是 13，S02 仍是 1。屏幕上的数以终端打印的「日峰值病害数量」「日 S03」「日 S02」为准。

点「小时」回到上一节。点列表的「查询」或「清除」时，地址栏里的 `grain` 还在。

没有桶时，这一块写「该粒度下没有病害高发。」

## 验收

- `make demo-disease-hotspot` 在 API 与对象存储已启动时退出码 0，并打印小时和日两个地址。
- 小时截图同一屏能读到「高发时段」和「高发棚区」。峰值那一行标着「峰值」，S03 的条比 S02 长，并标着「最高」。
- 日截图仍是这两张表，S03 高于 S02，较近的一天高于 2 日前。

`make demo-disease-list`、`make demo-disease-grade-filter` 与 `make demo-disease-env-detail` 不改。不改接入观测。不改 `GET /api/v1/diseases/peaks` 的参数。
