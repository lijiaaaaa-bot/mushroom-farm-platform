# 病害记录可查可见

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录：

```bash
make demo-disease-list
```

命令读取 `packages/contracts/fixtures/recognition.demo-one.json`，只改本次请求：摄像头 `CAM-DIS-01`，病害数量 2，病害等级 1，识别时间改成当前时刻，幂等键改成 `demo-disease-list-<毫秒>`。样例文件里的 `CAM-DEMO-01`、病害数量 1、病害等级 1 不改。温度仍是 22.5℃。病害数量 2 低于种子规则「病害数量一般」的 5，病害等级 1 低于「病害等级一般」的 2，所以这条识别不新开告警。

然后读三份接口：

- `GET /api/v1/diseases?cameraCode=CAM-DIS-01&pageSize=50` 里有这一条。时间、棚区 S01、位置 `CAM-DIS-01`、病害等级 1、病害数量 2 都在，并且有抓拍对象键。
- `GET /api/v1/diseases/:id` 与列表这一行一致。
- `GET /api/v1/diseases?cameraCode=CAM-DIS-01&diseaseLevel=3&pageSize=50` 是空的，`total` 为 0。

抓拍要能从对象存储读回，并且字节与样例 JPEG 一致。对象存储没起来时命令失败。

终端打印这三行地址：

```text
病害列表: http://127.0.0.1:43123/diseases?cameraCode=CAM-DIS-01
病害详情: http://127.0.0.1:43123/diseases/<id>
对照列表: http://127.0.0.1:43123/diseases?cameraCode=CAM-DIS-01&diseaseLevel=3
```

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

## 1. 列表有行

打开终端里的「病害列表」。表里至少一行：

| 时间 | 棚区 | 位置 | 病害等级 | 病害数量 | 图片 |
| --- | --- | --- | --- | --- | --- |
| 上海时间 | S01 | CAM-DIS-01 | 轻度（1） | 2 | 有图 |

位置是这条识别的摄像头编号。时间以终端打印的时刻为准，页面按上海时间显示到分钟。

没有这一行，或写成「暂无病害记录。」，都算没对上。

## 2. 详情能展开字段

点这一行的「打开」，或直接打开终端里的「病害详情」。顶栏是「病害详情」。这一页要能读到：

| 标签 | 值 |
| --- | --- |
| 时间 | 与列表同一时刻 |
| 棚区 | S01 |
| 位置 | CAM-DIS-01 |
| 病害等级 | 轻度（1） |
| 病害数量 | 2 |
| 病害图片 | 样例 JPEG，能看见图 |

没有图时这一页写「无病害图片」。本命令要求有图。同期环境在这一页下方；没有环境读数时写「该时间窗内无环境读数」。

点「返回病害记录」回到刚才的列表，筛选还在。

## 3. 对照

打开终端里的「对照列表」。病害等级是「严重」。页面写「没有符合条件的病害记录。」，表里没有 `CAM-DIS-01`。

和第一节的列表并排时，一份有行，一份没有。

也可以在 `/diseases` 自己填：位置 `CAM-DIS-01`，病害等级「轻度」，点「查询」。改成「严重」后再查，应看到空列表。点「清除」不再按这台摄像头和这个等级过滤。开始或结束不是有效时间时，页面写「时间筛选无效」，不把空表当成没有记录。

## 验收

- `make demo-disease-list` 在 API 已启动时退出码 0，并打印列表、详情、对照三个地址。
- 列表截图里至少有一行，能读到时间、棚区、位置、病害等级。
- 详情截图里上述字段都在，并且有病害图片。
- 对照截图是空列表，文案是「没有符合条件的病害记录。」

`make demo-report-xlsx` 与 `make demo-alert-by-device` 不改。样例文件不改。不导出 xlsx。
