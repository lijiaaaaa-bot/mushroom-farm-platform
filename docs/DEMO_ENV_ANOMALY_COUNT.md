# 异常环境点位数

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录：

```bash
make demo-env-anomaly-count
```

命令读取 `packages/contracts/fixtures/environment.demo-history.json`，只作报文底稿。样例文件不改。不新建阈值规则，也不改种子规则。计数用的是已经启用的环境阈值：

| 规则 | 指标 | 阈值 | 超出 |
| --- | --- | --- | --- |
| 温度过高 | `temperature_high` | 28 | 大于 28 |
| 温度过低 | `temperature_low` | 12 | 小于 12 |
| 湿度过低 | `humidity_low` | 70 | 小于 70 |
| 湿度过高 | `humidity_high` | 98 | 大于 98 |
| 二氧化碳过高 | `co2_high` | 2000 | 大于 2000 |
| 基质偏干 | `substrate_moisture_low` | 50 | 小于 50 |

等于阈值不算超出。规则若停用、改了阈值，或不再是全场规则，命令失败，不会去改它。棚上另有已启用的环境规则时，同样参加判断：全场规则和该棚规则，有一条突破即算这台传感器异常。

写入当天三台传感器，观测时间都在运行时刻的上海自然日里：

| 棚区 | 传感器 | 温度 | 湿度 | CO₂ | 基质含水率 | 点位 |
| --- | --- | --- | --- | --- | --- | --- |
| `S01` | `SENSOR-EAC-01` | 32℃ | 55% | 800 | 65% | 异常（温度、湿度两项，仍计 1） |
| `S02` | `SENSOR-EAC-02` | 22℃ | 80% | 900 | 40% | 异常（基质含水率） |
| `S01` | `SENSOR-EAC-OK` | 22℃ | 80% | 800 | 65% | 正常 |

另写昨天一台 `SENSOR-EAC-YDAY`（棚区 `S01`）：40℃ / 80% / CO₂ 800 / 基质含水率 65%。它不进今天的点数。对照 `SENSOR-EAC-NONE` 不写入。

幂等键是 `demo-env-anomaly-count-<传感器>-<上海日>`。同一上海日再跑不另建一行，并重写这台传感器当天的日桶。样例里的 `SENSOR-HIST-01`、温度 23.1 不改。

超阈读数会碰到已有种子规则，接入时可能留下未闭合告警。命令只关闭这四台演示传感器上的未闭合告警，备注「异常环境点位演示后关闭」。不关闭其他传感器，不认领，不改规则。点数不读告警表。

然后读当天的环境列表和 `GET /api/v1/dashboard/overview`：

- `SENSOR-EAC-01` 当天是 32℃ / 55% / CO₂ 800 / 基质含水率 65%。温度和湿度都超出，仍是 1 个点。
- `SENSOR-EAC-02` 当天基质含水率 40%，是另 1 个点。
- `SENSOR-EAC-OK` 四项都在种子阈值内，不计。
- 全园点数是当天传感器日桶里、至少一项超出适用于该棚的已启用环境阈值的传感器个数。棚级行（`camera_code` 为空）不计入。不扫 `environment_readings` 来出这个数，也不把同一次超限的多条读数相加。
- `SENSOR-EAC-YDAY` 的观测时间在昨天，当天列表是空的。`SENSOR-EAC-NONE` 当天也是空的。
- 总览的 `envAnomalyPointCount` 与上面这个整数相同。没有超限点位时是 0。

口径：上海自然日的环境日桶。每个传感器取当天 `value`。一个传感器是一个点位。今天没有环境日桶时是 0。这与全园环境参数均值同一类「上海今日、日桶、按传感器、全场」口径，这里是计数不是平均。`overview.env` 仍是近 24 小时棚级小时桶均值。全园环境参数均值、在养三数、当日病害、今日识别、今日抓拍都不改。

终端第一行是旁注。干净的当天、没有别的超阈传感器时：

```text
异常环境点位数 2
```

当天已有别的超阈传感器时，这个数会按同一口径变大，仍然等于总览接口，也等于下面两个页面上的旁注和卡上的数字。只有这两台异常时，必须是 2。

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

## 1. 总览

打开 http://127.0.0.1:43123/ 。「全园环境参数均值」那一块下面有一张卡，标题是「异常环境点位数」。卡上的数字与下面一行旁注相同。干净当天这一行是「异常环境点位数 2」。这一页不画异常点的分布。

## 2. 基地大屏

打开 http://127.0.0.1:43123/big-screen 。指标条下方同样一张卡，标题、数字和旁注与总览相同。点某一个棚之后，这一块仍是全园点数，不改成单棚最近识别上的温度。

## 3. 对照

`SENSOR-EAC-YDAY` 在昨天，不把今天的点数加 1。`SENSOR-EAC-NONE` 当天没有读数。`SENSOR-EAC-OK` 不计。干净的当天、没有别的超阈传感器时，总览卡和大屏卡都是 2，旁注是「异常环境点位数 2」。再跑一次仍是这个数。

## Mac 截图验收

在 Mac 上 API 已监听 41821、页面已打开时：

1. 跑 `make demo-env-anomaly-count`。终端第一行与总览、大屏旁注相同。
2. 截总览 `/`：标题是「异常环境点位数」，能读到一个数字，与旁注相同。干净当天旁注是「异常环境点位数 2」。
3. 截基地大屏 `/big-screen`：同样的标题、数字和同一句旁注。

## 验收

- `make demo-env-anomaly-count` 在 API 已启动时退出码 0。终端第一行是「异常环境点位数 N」。干净当天是 2。
- 总览 `/` 与基地大屏 `/big-screen` 上的标题、数字和旁注与这一行相同。
- 对照传感器 `SENSOR-EAC-NONE` 当天是 0 条。`SENSOR-EAC-YDAY` 不在今天。`SENSOR-EAC-01` 是 32℃ / 55% / 800 / 65%。`SENSOR-EAC-02` 基质含水率是 40%。`SENSOR-EAC-OK` 不计。

不改全园环境参数均值、在养蘑菇总数、当日病害总数、今日识别次数、今日抓拍总量的旁注。不改 `/capture-preview`、单棚四数、生长增量、病害趋势、环境 24 小时。不改 `overview.env`。不改接入观测。不改样例文件。不画异常环境点位分布。

本机若没有 Docker，或 API 没在 41821 监听，命令不会对接口实发。Mac 上再跑 `make demo-env-anomaly-count`，并按上面的地址截图。
