# 生长趋势按日周月可对照

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录：

```bash
make demo-growth-grain
```

命令读取 `packages/contracts/fixtures/recognition.demo-growth-trend.json`，样例文件不改。本次请求把摄像头写成 `CAM-GG-01`、棚区仍是 `S01`，识别时间改到六个上海日，幂等键是 `demo-growth-grain-CAM-GG-01-<上海日>`。数量仍用样例里的三档：周一蘑菇 8、成熟 2；较早两周的周三蘑菇 14、成熟 5；最近一周的周三蘑菇 21、成熟 8。这六个日都落在近 30 个上海日里，分成三个已经结束的周，每周两天。同一天再跑沿用这一行，不另建，样本数不加。`CAM-GT-01` 与 `recognition.demo-one.json` 里的 `CAM-DEMO-01` 不改。

病害数量 0，病害等级 0，温度 22.5℃。成熟占比低于种子规则「成熟占比一般」的 0.6。对象存储没起来时，第一次写入失败。

然后读三份 `days=30` 的接口，摄像头都是 `CAM-GG-01`：

- `grain=day` 是 6 个点，周期是六个上海日，里面有蘑菇 8。
- `grain=week` 是 3 个点，周期是三个周一。蘑菇数是该周周三（14 或 21），不是周一的 8。样本数是该周两天相加。
- `grain=month` 是 1 个或 2 个点，周期是 `YYYY-MM`。点数少于周。

日的点数多于周，周的点数多于月。

终端打印这三个地址：

```text
日: http://127.0.0.1:43123/growth-trends?days=30&grain=day&shedCode=S01&cameraCode=CAM-GG-01
周: http://127.0.0.1:43123/growth-trends?days=30&grain=week&shedCode=S01&cameraCode=CAM-GG-01
月: http://127.0.0.1:43123/growth-trends?days=30&grain=month&shedCode=S01&cameraCode=CAM-GG-01
```

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

## 1. 日

打开终端里的「日」。页顶能读到：

| 位置 | 值 |
| --- | --- |
| 棚区下拉 | 一号菇棚（S01） |
| 文字 | 棚区 S01 · 30 天 |
| 粒度 | 粒度 日 · 共 6 个点 |
| 摄像头 | CAM-GG-01 |
| 按钮 | 「日」是当前选中 |

表头是「日期」。至少六行，对象都是 `CAM-GG-01`。能看到蘑菇 8 的那一天。不要停在「没有日聚合，未绘制曲线。」

## 2. 周

打开终端里的「周」，或在上一页点「周」。文字变成「棚区 S01 · 周」。粒度一行是「粒度 周 · 共 3 个点」，后面跟着三个带「（周）」的周一。表头是「周」。行数比日少。表里没有单独的蘑菇 8 那一天；这一周的蘑菇数是周三的 14 或 21。点「日」回到上一节，点数回到 6，蘑菇 8 那一行又出现。

## 3. 月

打开终端里的「月」，或在周页面点「月」。文字变成「棚区 S01 · 月」。粒度一行是「粒度 月 · 共 1 个点」或「共 2 个点」，点数比周少。周期写成 `2026-09（月）` 这种 `YYYY-MM（月）`，不再是周一。表头是「月」。点「周」回到上一节。

和日、周并排时，三份的点数和周期文字都不一样。

## 验收

- `make demo-growth-grain` 在 API 已启动时退出码 0，并打印日、周、月三个地址，以及三个彼此不同的点数。
- 日截图能读到「粒度 日 · 共 6 个点」、日期和蘑菇 8。
- 周截图能读到「粒度 周 · 共 3 个点」和「（周）」，行数比日少，看不到单独的蘑菇 8。
- 月截图能读到「粒度 月 · 共 1 个点」或「共 2 个点」和「（月）」，点数比周少。
- 在同一页依次点「日」「周」「月」，上述文字随按钮变化。

`make demo-growth-trend` 不改。不改接入观测。不改产量预测。不导出 xlsx。
