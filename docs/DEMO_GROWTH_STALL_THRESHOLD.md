# 菌盖生长停滞阈值与生长异常预警

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录：

```bash
make demo-growth-stall-threshold
```

命令用管理员账号读写已有的阈值规则，不另建一套配置。没有名为「生长异常预警」、指标为菌盖生长停滞、棚区为空（全场）的规则时，`POST /api/v1/alert-rules` 新建一条：级别提示，窗口 720 分钟。然后 `PATCH /api/v1/alert-rules/:id`，把阈值写成 2，并保持启用。同一指标 `live_growth_stall` 上其他已启用的规则会改成停用，避免总览改读另一条更小的阈值。种子规则不改，包括「生长停滞」仍是指标 `growth_stall`、阈值 0.05。那条仍按单条识别开告警。本条不按单条识别新开告警。

然后读取 `packages/contracts/fixtures/recognition.demo-one.json`，只作报文底稿。样例文件不改。写入连续三个上海日的识别，识别时间是运行时刻往前 2 天、1 天和当天，时钟不变，所以仍落在对应的上海自然日里：

| 棚区 | 摄像头 | 上海日 | 蘑菇数 | 成熟 | 菌盖直径 | 病害数量 |
| --- | --- | --- | --- | --- | --- | --- |
| `S01` | `CAM-GST-01` | 前天、昨天、今天 | 10 | 2 | 4 | 0 |
| `S02` | `CAM-GST-ZERO` | 今天 | 0 | 0 | 不写 | 0 |

病害等级 0。温度 22.5℃，湿度 88%，CO₂ 900，基质含水率 70%。成熟占比 2/10，低于种子规则「成熟占比一般」的 0.6。病害数量低于「病害数量一般」的 5。病害等级低于「病害等级一般」的 2。幂等键是 `demo-growth-stall-threshold-<摄像头>-<上海日>`。同一上海日再跑不另建一行。样例里的 `CAM-DEMO-01`、蘑菇数 12、病害数量 1、菌盖直径 3.2 / 4.8 / 6.1、AI抓拍图不改。本次请求不带抓拍。

日桶用已有的 `cap_diameter_mean`。摄像头行是这一台当天的菌盖均值，棚级行不计入。窗口是今天往前共 30 个上海日，与生长趋势的 30 日相同。每天的均值先保留两位小数，再和前一个上海日相减。从今天往前，相邻两日都有值且增量 ≤ 0，记 1 个停滞日。增量为正，或中间缺了一天，连续天数就停。今天没有菌盖日桶时，这台是 0。全场取各摄像头里最大的那个天数。有棚区的规则只比该棚。

`CAM-GST-01` 三天的菌盖直径都是 4。相邻两日增量是 0 和 0。以今天为终点的连续停滞天数是 2。`CAM-GST-ZERO` 不写菌盖，不产生菌盖日桶，天数是 0，不把全场抬高。

种子规则「生长停滞」比较的是窗内菌盖差小于 0.05。这三天的增量是 0，会在 `CAM-GST-01` 留下未闭合告警。命令只关闭这台摄像头上指标为 `growth_stall` 的未闭合告警，备注「生长停滞演示后关闭」。不关别的摄像头，不改认领。指标 `live_growth_stall` 的待确认列表里没有告警行。

然后读 `GET /api/v1/dashboard/overview`。阈值是全场规则上的整数天数。当前停滞天数 ≥ 2 时预警生效。

终端第一行是旁注。干净的当天、没有别的摄像头以今天为终点的连续停滞天数大于 2 时：

```text
生长异常预警 停滞≥2 当前2
```

当天已有更长的停滞时，当前天数不小于 2，旁注变成「生长异常预警 停滞≥2 当前N」，仍然等于总览接口，也等于总览页上的横幅。

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

## 1. 总览

打开 http://127.0.0.1:43123/ 。病害预警下面有一块「生长异常预警」。菌盖生长停滞阈值的输入框是 2。配置旁注是「菌盖生长停滞阈值 2 · 全场 · 当前停滞 N」。当前停滞达到 2 时，下面有一条横幅，文案与终端第一行相同。干净当天是「生长异常预警 停滞≥2 当前2」。超管和生产管理员可以改输入框并点「保存」，保存后重新读总览。查看角色看得到阈值，没有「保存」。

`/alert-rules` 里同一条规则的指标是「菌盖生长停滞」，阈值是 2，棚区是全场，启用是「是」。总览这一块就是改这条规则，不另存一份阈值。

## 2. 对照

`CAM-GST-ZERO` 不写菌盖，不把全场停滞天数抬高。`CAM-GST-NONE` 当天没有识别。干净的当天、没有更长停滞时，横幅是「生长异常预警 停滞≥2 当前2」。再跑一次仍是这个旁注。

## Mac 截图验收

在 Mac 上 API 已监听 41821、页面已打开时：

1. 跑 `make demo-growth-stall-threshold`。终端第一行与总览横幅相同。
2. 截总览 `/`：标题是「生长异常预警」，阈值输入框能读到 2，横幅能读到「生长异常预警 停滞≥2 当前N」。干净当天 N 是 2。
3. 配置旁注能读到「菌盖生长停滞阈值 2 · 全场 · 当前停滞 N」，N 与横幅里的当前数相同。

## 验收

- `make demo-growth-stall-threshold` 在 API 已启动时退出码 0。终端第一行是「生长异常预警 停滞≥2 当前N」。干净当天 N 是 2。当前停滞不小于 2。
- 总览 `/` 上的阈值、配置旁注和横幅与这一行相同。
- `GET /api/v1/dashboard/overview` 的 `growthStallThreshold` 是 2，`growthStallActive` 是 true，`growthStallCurrent` 是 N，`growthStallNote` 是「生长异常预警 停滞≥2 当前N」，`growthStallShedCode` 是空。
- 对照摄像头 `CAM-GST-NONE` 当天是 0 条。`CAM-GST-ZERO` 蘑菇 0、成熟 0、没有菌盖日桶。`CAM-GST-01` 连续三天蘑菇 10、成熟 2、菌盖直径 4。
- 这两台摄像头上没有指标为菌盖生长停滞的待确认告警。种子「生长停滞」在 `CAM-GST-01` 上打开的告警已被命令关闭。

不改采摘提醒、病害预警、在养蘑菇总数、当日病害总数、今日识别次数、今日抓拍总量、全园环境参数均值、异常环境点位数、全局设备在线的旁注。不改基地大屏。不改接入观测。不改样例文件。不改 `/shed-growth-delta` 的旁注。不画点位分布。不改病害详情同期环境，不改告警认领。

本机若没有 Docker，或 API 没在 41821 监听，命令不会对接口实发。Mac 上再跑 `make demo-growth-stall-threshold`，并按上面的地址截图。
