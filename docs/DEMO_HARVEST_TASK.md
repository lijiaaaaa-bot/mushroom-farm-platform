# 采摘任务可查可排

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。`make api` 可设 `MQTT_ENABLED=false`。

在仓库根目录：

```bash
make demo-harvest-task
```

命令用管理员账号。账号 `admin`，密码 `Admin@123456`。

1. 读取 `packages/contracts/fixtures/recognition.demo-one.json`，只改本次请求，样例文件不改。写两次识别，识别时间都是当前时刻，幂等键是 `demo-harvest-task-<摄像头>-<毫秒>`。
   - `CAM-HT-01`，棚区 `S01`，成熟数 5，蘑菇数 12。温度、病害、抓拍仍用样例。
   - `CAM-HT-02`，棚区 `S01`，成熟数 9，蘑菇数 17。其余仍用样例。
2. 成熟数 5 对蘑菇数 12、成熟数 9 对蘑菇数 17，都低于种子规则「成熟占比一般」的 0.6。病害数量 1 低于「病害数量一般」的 5，病害等级 1 低于「病害等级一般」的 2，温度 22.5℃ 低于「温度过高」的 28。这两条识别不因这些规则新开告警。
3. `POST /api/v1/harvest/tasks/generate?date=<上海日期>`。当日成熟数大于 0 的摄像头进入清单。已有任务只更新数量，保留人员和班次。`CAM-HT-01`、`CAM-HT-02` 都在。当天若还有别的成熟摄像头，行数会更多，这两行仍在。
4. `PATCH /api/v1/harvest/tasks/:id`：`CAM-HT-01` 人员王早、班次上午、状态已排；`CAM-HT-02` 人员李午、班次下午、状态已排。
5. 再读 `GET /api/v1/harvest/tasks?date=<同一上海日期>`。两行的人员、班次、成熟数与上面一致。排班计数里上午至少 1 条、下午至少 1 条，未排是数字。行数与生成时相同。

抓拍要能写入对象存储。对象存储没起来时命令失败。

终端打印日期、生成行数、排班计数、人员和班次对照，以及可打开的地址：

```text
日期: <上海日期>
生成行数: 2
排班: 上午 1 条，下午 1 条，未排 0 条
对照: CAM-HT-01 王早 上午；CAM-HT-02 李午 下午
打开: http://127.0.0.1:43123/harvest?date=<上海日期>
```

生成行数、上午、下午、未排以接口返回为准。上面的 2、1、1、0 是当天只有这两台成熟摄像头时的数。

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。再打开终端里的地址。

## 1. 生成后有清单行

页面向下找到「每日采摘任务清单」。点「生成当日清单」后，不用整页刷新，这一段就有行。

排班辅助写成「上午 … 条，下午 … 条，未排 … 条」。还没保存人员时，这两行的人员是空的，班次是「未排」，状态是「待采」，未排条数至少包含这两行。

| 棚区 | 摄像头 | 成熟 | 人员 | 班次 | 状态 |
| --- | --- | --- | --- | --- | --- |
| S01 | CAM-HT-01 | 5 | 空 | 未排 | 待采 |
| S01 | CAM-HT-02 | 9 | 空 | 未排 | 待采 |

没有行，或写成「当日无采摘任务。」，都算没对上。

截图：`docs/evidence/demo-harvest-task/after-generate.png`。要能读到「每日采摘任务清单」、排班辅助的上午/下午/未排，以及 `CAM-HT-01`、`CAM-HT-02` 两行。

## 2. 人员、班次可见，保存后立刻可见

在 `CAM-HT-01` 这一行人员填「王早」，班次选「上午」，点「保存排班」。在 `CAM-HT-02` 这一行人员填「李午」，班次选「下午」，点「保存排班」。

保存后这一段重新读取。输入框里是刚保存的人员和班次，状态是「已排」。排班辅助的上午、下午条数跟着变，未排条数去掉已经排了班次的行。

| 棚区 | 摄像头 | 成熟 | 人员 | 班次 | 状态 |
| --- | --- | --- | --- | --- | --- |
| S01 | CAM-HT-01 | 5 | 王早 | 上午 | 已排 |
| S01 | CAM-HT-02 | 9 | 李午 | 下午 | 已排 |

对照就是：`CAM-HT-01` 王早、上午，`CAM-HT-02` 李午、下午。成熟数仍是 5 和 9。

也可以只跑命令，然后打开终端里的地址。看到的是上表，不是两行都未排。

查看人员没有「生成当日清单」和「保存排班」，人员和班次是文字。超管、生产管理员、棚区负责人可以写。

截图：`docs/evidence/demo-harvest-task/after-assign.png`。要能同时看出王早、上午、李午、下午，以及排班辅助里的上午、下午、未排。

## 验收

- `make demo-harvest-task` 在 API 已启动时退出码 0，并打印日期、生成行数、上午/下午/未排、人员班次对照和 `/harvest?date=` 地址。
- 生成后的截图里有清单行，能读到 `CAM-HT-01`、`CAM-HT-02` 和排班辅助计数。
- 排班后的截图里能读到王早、上午、李午、下午。
- 样例文件里的 `CAM-DEMO-01` 不改。

`make demo-harvest-list` 与 `make demo-harvest-filter` 不改。那两条仍只写采摘记录，不生成采摘任务。不改接入观测。不出菇批次，不算产量预估。
