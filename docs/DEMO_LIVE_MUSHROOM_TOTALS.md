# 实时在养蘑菇总数

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录：

```bash
make demo-live-mushroom-totals
```

命令读取 `packages/contracts/fixtures/recognition.demo-one.json`，只作报文底稿。样例文件不改。写入当天三条识别，识别时间都在运行时刻的上海自然日里：

| 棚区 | 摄像头 | 蘑菇数 | 成熟 | 病害数量 |
| --- | --- | --- | --- | --- |
| `S01` | `CAM-LMT-01` | 20 | 8 | 0 |
| `S01` | `CAM-LMT-02` | 10 | 3 | 0 |
| `S02` | `CAM-LMT-ZERO` | 0 | 0 | 0 |

病害等级 0。温度 22.5℃，湿度 88%，CO₂ 900，基质含水率 70%。成熟占比低于种子规则「成熟占比一般」的 0.6。病害数量低于「病害数量一般」的 5。病害等级低于「病害等级一般」的 2。幂等键是 `demo-live-mushroom-totals-<摄像头>-<上海日>`。同一上海日再跑不另建一行。样例里的 `CAM-DEMO-01`、蘑菇数 12、病害数量 1、AI抓拍图不改。本次请求不带抓拍，对象存储没起来也能写入。

然后读当天的识别列表和 `GET /api/v1/dashboard/overview`：

- `CAM-LMT-01` 当天蘑菇 20、成熟 8。`CAM-LMT-02` 当天蘑菇 10、成熟 3。`S01` 先把这两台当日最新相加：蘑菇 30、成熟 11，待成熟在相加之后再算，是 `max(0, 30 − 11) = 19`。
- `CAM-LMT-ZERO` 在 `S02`，蘑菇 0、成熟 0，待成熟 0。这一棚加进全场之后，三数不变。
- 同一天 `cameraCode=CAM-LMT-NONE`（棚区 `S01`）的列表是空的。空摄像头不增加三数。
- 总览的 `liveMushroomTotal` 是在养蘑菇总数，`liveMatureTotal` 是成熟可采摘总数，`liveImmatureTotal` 是待成熟数量。今日按识别时间 `recognizedAt` 的上海自然日。各棚只加摄像头当日日桶最新的 `mushroom_count`、`mature_count`，待成熟在该棚相加之后再算，全场再把各棚的蘑菇、成熟、待成熟分别相加。棚级行不重复计入。不扫识别明细。这不是当日病害总数，也不是今日识别次数或今日抓拍总量。

终端第一行是旁注。干净的当天、没有别的蘑菇或成熟日桶时：

```text
在养蘑菇总数 30 · 成熟可采摘总数 11 · 待成熟数量 19
```

当天已有别的摄像头时，这三个数会按同一口径变大或持平，仍然等于总览接口，也等于下面两个页面上的旁注和卡上的数字。在养与成熟正好是 30 和 11 时，待成熟必须是 19。

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

## 1. 总览

打开 http://127.0.0.1:43123/ 。页顶「今日识别次数」「今日抓拍总量」「当日病害总数」下面另有三张卡，文案是「在养蘑菇总数」「成熟可采摘总数」「待成熟数量」。卡上的数字与下面一行旁注相同。干净当天这一行是「在养蘑菇总数 30 · 成熟可采摘总数 11 · 待成熟数量 19」。

## 2. 基地大屏

打开 http://127.0.0.1:43123/big-screen 。指标条下方同样三张卡，文案与数字和总览相同。三张卡下面同一句旁注。

## 3. 对照

`CAM-LMT-ZERO` 是 0，不把全场抬高。`CAM-LMT-NONE` 当天没有识别。干净的当天、没有别的蘑菇或成熟日桶时，总览三张卡和大屏三张卡都是 30、11、19，旁注是「在养蘑菇总数 30 · 成熟可采摘总数 11 · 待成熟数量 19」。再跑一次仍是这个数。

## Mac 截图验收

在 Mac 上 API 已监听 41821、页面已打开时：

1. 跑 `make demo-live-mushroom-totals`。终端第一行与总览、大屏旁注相同。
2. 截总览 `/`：三张卡的标题分别是「在养蘑菇总数」「成熟可采摘总数」「待成熟数量」，卡上数字与旁注里的三个数相同。干净当天旁注是「在养蘑菇总数 30 · 成熟可采摘总数 11 · 待成熟数量 19」。
3. 截基地大屏 `/big-screen`：同样三张卡和同一句旁注，三个数字与总览一致。

## 验收

- `make demo-live-mushroom-totals` 在 API 已启动时退出码 0。终端第一行是「在养蘑菇总数 N · 成熟可采摘总数 M · 待成熟数量 K」。干净当天 N、M、K 是 30、11、19。在养不小于 30，成熟不小于 11。在养与成熟正好是 30 与 11 时，待成熟是 19。
- 总览 `/` 与基地大屏 `/big-screen` 上的三张卡和旁注与这一行相同。
- 对照摄像头 `CAM-LMT-NONE` 当天是 0 条。`CAM-LMT-ZERO` 蘑菇 0、成熟 0。`CAM-LMT-01` 蘑菇 20、成熟 8。`CAM-LMT-02` 蘑菇 10、成熟 3。

不改今日识别次数、今日抓拍总量、当日病害总数的旁注。不改 `/capture-preview`、单棚四数、生长增量、病害趋势、环境 24 小时、病害高发、成熟率。不改接入观测。不改样例文件。不画病害点位分布。

本机若没有 Docker，或 API 没在 41821 监听，命令不会对接口实发。Mac 上再跑 `make demo-live-mushroom-totals`，并按上面的地址截图。
