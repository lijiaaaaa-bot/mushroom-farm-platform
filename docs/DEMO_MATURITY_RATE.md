# 成熟率变化趋势可查可见

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录：

```bash
make demo-maturity-rate
```

命令读取 `packages/contracts/fixtures/recognition.demo-growth-trend.json`，样例文件不改。本次请求改成摄像头 `CAM-MR-01`、棚区 `S01`，写入四个上海日：

| 往前的天数 | 蘑菇 | 成熟 | 成熟率 |
| --- | --- | --- | --- |
| 5 | 0 | 0 | — |
| 3 | 20 | 2 | 10% |
| 1 | 20 | 6 | 30% |
| 0（当天） | 20 | 10 | 50% |

成熟率是成熟数 ÷ 蘑菇数，写成百分数，保留一位。蘑菇数为 0 时接口里的 `maturityRate` 是空，页面写「—」，曲线不计这一点。10%、30%、50% 后一天更高。相邻有数的两点，升降写成「升 20」。幂等键是 `demo-maturity-rate-CAM-MR-01-<上海日>`。同一天再跑沿用这一行，不另建。样例里的 `CAM-GT-01` 不改。`recognition.demo-one.json` 里的 `CAM-DEMO-01` 不改。

病害数量 0，病害等级 0，温度 22.5℃。有蘑菇的三天成熟占比是 0.1、0.3、0.5，低于种子规则「成熟占比一般」的 0.6，不因成熟占比新开告警。对象存储没起来时，第一次写入失败。

然后读 `GET /api/v1/growth-trends?days=7&shedCode=S01&cameraCode=CAM-MR-01`。`CAM-MR-01` 含上面四天。蘑菇数、成熟数和成熟率与终端一致。至少两个点的成熟率不同，近日高于前几日。

终端打印这一行地址：

```text
打开: http://127.0.0.1:43123/growth-trends?days=7&shedCode=S01&cameraCode=CAM-MR-01
```

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

## 同一页读到成熟率

打开终端里的「打开」。页顶能读到：

| 位置 | 值 |
| --- | --- |
| 棚区下拉 | 一号菇棚（S01） |
| 文字 | 棚区 S01 · 7 天 |
| 旁注 | 成熟率 10% → 30% → 50%（升） |
| 摄像头 | CAM-MR-01 |

页面向下有成熟率曲线。纵轴带「%」。曲线至少两个点，后一天高于前一天。蘑菇为 0 的那天不画进这条曲线。

再往下是表。四行都是 `CAM-MR-01`。成熟率列是「—」「10%」「30%」「50%」。升降列在 10% 到 30%、30% 到 50% 两处写成「升 20」。蘑菇为 0 的那一行成熟率是「—」。

## 验收

- `make demo-maturity-rate` 在 API 已启动时退出码 0，并打印上面的页面地址。
- 同一页截图能读到成熟率百分数，并且至少两个点不一样，能看出升高。
- 蘑菇为 0 的那一行是「—」，不写成 0%。

`make demo-growth-trend` 仍写入 `CAM-GT-01`。`make demo-growth-grain` 仍写入 `CAM-GG-01`。不改这两条命令。不改接入观测。不改样例文件。
