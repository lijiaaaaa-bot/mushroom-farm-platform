# 两个角色登录后菜单不同

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

## 1. 写成两个已知账号

在仓库根目录：

```bash
make demo-rbac
```

命令用种子超管 `admin` / `Admin@123456` 登录。再 `POST /api/v1/users`，把 `viewer` 写成密码 `Viewer@123456`、角色查看、棚号 `S01`。账号已在时带 `resetPassword: true`，重设密码、显示名、角色和棚号，并重新启用，不另建一行。不改 `admin`、`producer`、`shedlead`。

然后用查看密码再登录一次，核对：

| 检查 | 超管 | 查看 |
|------|------|------|
| `GET /api/v1/users` | 200，列表里有 `admin` 和 `viewer`，没有密码 | 403 |
| `GET /api/v1/audit-logs` | 200 | 403 |
| `GET /api/v1/login-logs` | 200 | 403 |
| `GET /api/v1/sheds` | 含 S01 和 S02 | 含 S01，不含 S02 |

终端打印两边的菜单。超管有「审计」「用户」。查看没有这两项。其余项两边都有：总览、基地大屏、值班看板、设备、识别记录、环境读数、接入观测、病害、告警、阈值规则、采摘、生长趋势、棚间对比、出菇批次、报表、棚区。

不发识别，不发心跳，不改告警，不改阈值规则。

## 2. 在页面上对菜单

浏览器打开 http://127.0.0.1:43123/login 。

用 `admin` / `Admin@123456` 登录。侧栏最后两项是「审计」「用户」。

- http://127.0.0.1:43123/audit 上方是登录日志，下方是操作审计。
- http://127.0.0.1:43123/users 列出用户名、显示名、角色、棚区。超管棚区写「全场」。没有密码列。

退出后用 `viewer` / `Viewer@123456` 登录。侧栏没有「审计」和「用户」。顶栏仍有「基地大屏」和「值班看板」。

直接打开 http://127.0.0.1:43123/audit 或 http://127.0.0.1:43123/users ，页面回到总览 http://127.0.0.1:43123/ 。棚区页只有 S01，没有 S02。

生产管理员 `producer` / `Producer@123456` 看得到「审计」，看不到「用户」。这条命令不登录该账号。

`make demo-one-ingest`、`make demo-duty-board`、`make demo-alert-status-filter` 以及其他已有演示命令都不改。
