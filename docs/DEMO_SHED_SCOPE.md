# 棚区负责人只看到负责棚

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

这条对照的是数据范围：超管看多个棚，棚区负责人只看账号上的棚。菜单差异仍走 `make demo-rbac`（超管对查看），本命令不改那条。

## 1. 写成两个已知账号，并留下两棚告警

在仓库根目录：

```bash
make demo-shed-scope
```

命令用种子超管 `admin` / `Admin@123456` 登录。再 `POST /api/v1/users`，把 `shedlead` 写成密码 `Shed@123456`、角色棚区负责人、棚号只有 `S01`。账号已在时带 `resetPassword: true`，重设密码、显示名、角色和棚号，并重新启用，不另建一行。不改 `admin`、`producer`、`viewer`。

然后留下两条一般告警，时间是这次运行的时刻，所以会排在告警列表前面：

| 标题 | 棚区 | 摄像头 | 说明 |
|------|------|--------|------|
| 棚范围一号棚 | S01 | `CAM-SCOPE-S01` | 棚区 S01 负责人可见 |
| 棚范围二号棚 | S02 | `CAM-SCOPE-S02` | 棚区 S02 仅全场角色可见 |

同标题、同摄像头、同棚已在时不另建一行，只把这条的时间改到这次运行，不改状态。终端打印 `新建` 或 `沿用`。

接着用棚区负责人再登录一次，核对同一库里的三处：

| 检查 | 超管 | 棚区负责人 |
|------|------|------------|
| `GET /api/v1/sheds` | 含 S01 和 S02（种子还有 S03） | 只有 S01 |
| `GET /api/v1/dashboard/overview` 的 `shedCount` | 至少 2 | 1 |
| 总览最近告警 | 可含 S02 | 不含 S02 |
| `GET /api/v1/alerts?pageSize=100` | 含「棚范围一号棚」和「棚范围二号棚」 | 含「棚范围一号棚」，不含 S02 |
| `GET /api/v1/alerts?q=棚范围二号棚` | 有 S02 这一行 | 空列表 |

不发识别，不发心跳，不改接入观测。

## 2. 在三个页面上对同一库

浏览器打开 http://127.0.0.1:43123/login 。

先用 `admin` / `Admin@123456` 登录，看这三页：

- http://127.0.0.1:43123/sheds  
  表里编号有 S01、S02。种子棚还在时还有 S03。名称分别是一号菇棚、二号菇棚。
- http://127.0.0.1:43123/duty-screen  
  中部棚卡有「棚 S01 · 一号菇棚」和「棚 S02 · 二号菇棚」。底部「分棚今日识别」列出 S01 和 S02。底部「全场」里的棚区数字至少是 2，种子三棚时是 3。
- http://127.0.0.1:43123/alerts  
  前两行附近有「棚范围二号棚」（棚区 S02）和「棚范围一号棚」（棚区 S01）。
- http://127.0.0.1:43123/alerts?q=棚范围二号棚  
  页上写出「标题 棚范围二号棚」，表里有棚区 S02。

基地大屏 http://127.0.0.1:43123/big-screen 的棚区平面点位同样来自棚列表，点上能读到 S01 和 S02。截值班看板即可，大屏是同一范围。

退出后用 `shedlead` / `Shed@123456` 登录，再打开同样的地址：

- http://127.0.0.1:43123/sheds  
  只有编号 S01，没有 S02，也没有 S03。
- http://127.0.0.1:43123/duty-screen  
  只有一张「棚 S01 · 一号菇棚」。没有 S02 的棚卡，底部条上也没有 S02。棚区数字是 1。
- http://127.0.0.1:43123/alerts  
  有「棚范围一号棚」，棚区列是 S01。没有「棚范围二号棚」。
- http://127.0.0.1:43123/alerts?q=棚范围二号棚  
  页上仍写出「标题 棚范围二号棚」，下面是「暂无告警。」

生产管理员 `producer` / `Producer@123456` 与超管一样不限制棚。这条命令不登录该账号。

`make demo-rbac` 仍只对照超管和查看的菜单。`make demo-duty-board`、`make demo-one-alert` 以及其他已有演示命令都不改。
