# 当日病害总数

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。

在仓库根目录：

```bash
make demo-today-disease-count
```

命令读取 `packages/contracts/fixtures/recognition.demo-one.json`，只作报文底稿。样例文件不改。写入棚区 `S01` 的两台摄像头，各一条识别，识别时间都在运行时刻的上海自然日里：

| 摄像头 | 蘑菇数 | 成熟 | 病害数量 |
| --- | --- | --- | --- |
| `CAM-TDC-01` | 8 | 2 | 2 |
| `CAM-TDC-02` | 6 | 1 | 1 |

病害等级 1。温度 22.5℃，湿度 88%，CO₂ 900，基质含水率 70%。成熟占比低于种子规则「成熟占比一般」的 0.6。每条病害数量低于「病害数量一般」的 5。病害等级低于「病害等级一般」的 2。幂等键是 `demo-today-disease-count-<摄像头>-<上海日>`。同一上海日再跑不另建一行。样例里的 `CAM-DEMO-01`、蘑菇数 12、病害数量 1、AI抓拍图不改。本次请求不带抓拍，对象存储没起来也能写入。

然后读当天的识别列表和 `GET /api/v1/dashboard/overview`：

- `CAM-TDC-01` 当天病害数量 2，`CAM-TDC-02` 当天病害数量 1。两台病害数量字段合计是 3。
- 同一天 `cameraCode=CAM-TDC-NONE` 的列表是空的。终端写「对照 CAM-TDC-NONE: 当日病害 0」。
- 总览的 `todayDiseaseCount` 是当日病害总数。今日按识别时间 `recognizedAt` 的上海自然日。这个数是各棚当日日桶棚级 `disease_count` 相加。棚级行是各摄像头当天最新一条病害数量相加（按 `recognizedAt`），只加棚级行，不把摄像头行再加一遍。本演示每台只写一条，所以这两台对总数的贡献等于病害数量字段合计 2 + 1 = 3。同一摄像头当天再写入更晚的识别时，日桶改成较新的病害数量，不会把同一台的几次相加。这不是病害点位分布。

终端第一行是旁注，例如干净的当天、没有别的识别时：

```text
当日病害总数 3
```

当天已有别的识别时，这个数会更大，仍然等于总览接口，也等于下面两个页面上的旁注和卡上的数字。

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。

## 1. 总览

打开 http://127.0.0.1:43123/ 。页顶「今日识别次数」「今日抓拍总量」旁边一张卡是「当日病害总数」。下面一行旁注与终端第一行相同，例如「当日病害总数 3」。卡上的数字与这一行相同。

## 2. 基地大屏

打开 http://127.0.0.1:43123/big-screen 。指标条里同样有「当日病害总数」，数字与总览那张卡相同。指标条下方同一句旁注。

## 3. 对照

`CAM-TDC-NONE` 当天没有识别。干净的当天、没有别的识别时，总览卡和大屏指标都是 3，旁注是「当日病害总数 3」。再跑一次仍是这个数。

## 验收

- `make demo-today-disease-count` 在 API 已启动时退出码 0。终端第一行是「当日病害总数 N」，并且 N 不小于 3。
- 总览 `/` 与基地大屏 `/big-screen` 上的「当日病害总数」卡和旁注与这一行相同。
- 干净的当天、没有别的识别时，这一行是「当日病害总数 3」。再跑一次仍是这个数。
- 对照摄像头 `CAM-TDC-NONE` 当天是 0 条。`CAM-TDC-01` 病害数量 2，`CAM-TDC-02` 病害数量 1。

不改今日识别次数、今日抓拍总量的旁注。不改 `/capture-preview`、单棚四数、生长增量、病害趋势、环境 24 小时、病害高发、成熟率。不改接入观测。不改样例文件。不画病害点位分布。

本机若没有 Docker，或 API 没在 41821 监听，命令不会对接口实发。Mac 上再跑 `make demo-today-disease-count`，并按终端里的总览和大屏地址截图。
