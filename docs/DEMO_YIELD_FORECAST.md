# 产量预估可查可见

先把数据库和前后端跑起来（已经在跑就跳过）。三个终端：

```bash
make up && make migrate
make api
make web
```

API 监听 http://127.0.0.1:41821 。页面是 http://127.0.0.1:43123 。`make api` 可设 `MQTT_ENABLED=false`。

在仓库根目录：

```bash
make demo-yield-forecast
```

命令读取 `packages/contracts/fixtures/recognition.demo-yield-forecast.json`，写入摄像头 `CAM-YF-01`、棚区 `S01` 的三天识别。数量以样例为准：前 6 个上海日蘑菇 12、成熟 4；前 3 个上海日蘑菇 18、成熟 8；当天蘑菇 24、成熟 12。识别时间按运行时刻往前推，幂等键是 `demo-yield-forecast-CAM-YF-01-<上海日>`。同一天再跑沿用这一行，不另建。样例文件不改。`recognition.demo-one.json` 里的 `CAM-DEMO-01` 不改。

这三天都落在近 7 个上海自然日里，成熟数一天比一天大。病害数量 0，病害等级 0，温度 22.5℃，湿度 88%，CO₂ 900，基质含水率 70%。成熟占比低于种子规则「成熟占比一般」的 0.6。菌盖直径 3.2。对象存储没起来时，第一次写入失败。

算法用日桶增速：`GET /api/v1/harvest/bucket-forecast`。近 7 个上海自然日的棚级成熟日桶，用首尾差除以间隔天数得到增速，外推未来 3 日。响应标签是「估计」。数字是未来日的成熟数。棚区 `S01` 在这 7 日里只有这一台摄像头时，历史天数是 3，间隔 6 天，每日增速 1.33，未来三日成熟数是 13、15、16。当天若还有别的棚级成熟日桶，历史天数和未来成熟数以接口返回为准，终端照实打印，`days` 仍不是空的。

`GET /api/v1/harvest/yield-estimate` 仍是近 30 个连续上海自然日的线性外推。不满连续 30 天时只返回说明，`days` 为空。终端把这一份印成对照。

终端打印算法、历史跨度、未来日期和成熟数，以及可打开的地址：

```text
算法: 日桶增速
方法: 近 7 个上海自然日棚级成熟日桶首尾增速，外推未来 3 日
历史天数: 3
历史跨度: <最早上海日> 至 <当天>（间隔 6 天）
每日增速: 1.33
未来成熟数:
<明天>: 估计 13 成熟
<后天>: 估计 15 成熟
<大后天>: 估计 16 成熟
打开: http://127.0.0.1:43123/harvest
对照: 30 日线性 days 为空
```

上面的 3、1.33、13、15、16 是近 7 日只有 `CAM-YF-01` 这三天时的数。页面上的数与终端「未来成熟数」相同。

浏览器打开 http://127.0.0.1:43123/login ，账号 `admin`，密码 `Admin@123456`。再打开终端里的地址。页顶就是两块估计，不用往下翻到当日清单。

## 1. 页上有估计标签

「近 2–3 日成熟估计（30 日线性）」和「近 2–3 日成熟估计（日桶增速）」都在。两块都有琥珀色的「估计」。日桶增速这一块写出方法，以及「每日增速」。

截图：`docs/evidence/demo-yield-forecast/estimate-label.png`。要能读到这两块标题和「估计」。

## 2. 未来两到三日成熟数可读

日桶增速这一块列出未来日期。至少两天，命令成功时是三天。每一天写成「估计 <成熟数> 成熟」，日期是 `YYYY-MM-DD`。成熟数与终端「未来成熟数」一致。

截图：`docs/evidence/demo-yield-forecast/future-days.png`。至少两个未来日期和对应成熟数要能直接读出来。

## 3. 连续 30 日不够时只写说明

30 日线性这一块在历史不满连续 30 天时不列未来日期，文案含「有效历史不足」。日桶增速那一块仍有未来成熟数。两块并排时，一份是说明，一份是数字。

已经凑满连续 30 天时，这一块也会列出未来成熟数，终端对照改成「30 日线性也有 N 日」。本演示不靠凑满 30 天。

截图：`docs/evidence/demo-yield-forecast/thin-history.png`。要能读到「有效历史不足」，并且没有把日桶增速的未来成熟数抹掉。

## 验收

- `make demo-yield-forecast` 在 API 已启动时退出码 0，并打印算法「日桶增速」、历史跨度、未来 2–3 日的日期和成熟数，以及 `/harvest`。
- 估计标签截图能读到「估计」。
- 未来日期截图至少两天，成熟数肉眼可读。
- 样例文件里的 `CAM-DEMO-01` 不改。

`make demo-harvest-list`、`make demo-harvest-filter`、`make demo-harvest-task`、`make demo-fruiting-batch` 与 `make demo-growth-trend` 不改。不改接入观测。不改产量预估算法。不生成采摘任务。
