# 指挥台需求草稿（MVP）

## 目标

做一个给 D J 使用的**一页式项目进度小应用**：快速看清工作流、阻塞点、智能体入口和关键文档。它是项目进度指挥台，不是完整 Jira，也不是基地监控大屏。不要把它写成公安 / 雪亮风格，也不要把暗色当成验收硬约束。

## MVP 范围

### 必须有

- **工作流卡片**：名称、状态（已完成 / 进行中 / 阻塞）、负责人、最近更新时间、下一步。
- **阻塞区**：阻塞原因、影响范围、解除动作、状态。
- **Cloud agent 链接**：记录任务名称、会话/执行入口、当前结果；只保存真实可用链接，不生成假链接。
- **文档路径**：记录本地绝对路径或仓库相对路径，可点击打开/复制。
- **一页总览**：顶部统计，中央工作流，侧边阻塞与下一步；支持手动刷新。

### 明确不做

- 不做完整 Jira 的项目、权限、工时、Issue、Sprint、报表体系。
- 不做复杂审批流、多人协作、消息中心、自动排期。
- 不把聊天记录、日志和文档全文复制进应用；只保留索引和摘要。

## 页面与交互

- 单页总览，信息密度高但可扫读；状态灯使用绿 / 蓝 / 红，兼顾文字标签。不强制暗色。
- 默认显示当前项目和四块：**项目概况｜工作流｜阻塞｜下一步**。
- 点击工作流卡片展开：关联 agent、文档路径、验收记录。
- 点击路径可复制；本地路径不存在时显示“待确认”，不伪造可用状态。
- 支持新增、编辑、归档工作流和阻塞项；MVP 可先用本地 JSON / SQLite。

## 最小数据模型

```text
Project: id, name, stack, mode, updatedAt
Workstream: id, projectId, name, status, owner, nextAction, updatedAt
Blocker: id, workstreamId, reason, impact, unblockAction, status
AgentLink: id, workstreamId, label, urlOrRef, result
DocRef: id, workstreamId, label, path, exists, note
```

## 验收标准

- 打开页面即可在 10 秒内回答：现在做到哪、卡在哪、下一步是什么。
- 可维护至少 5 条工作流、3 条阻塞、10 个文档路径和 agent 入口。
- 所有状态与链接可追溯；没有 fake URL，阻塞不被绿色状态掩盖。
- 一页布局在桌面宽度下无需滚动即可看到总览核心信息（不强制暗色）。
