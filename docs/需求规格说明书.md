## 1. 引言

### 1.1 文档目的

定义智慧食用菌基地**管理汇聚平台**的功能、非功能、接口与数据需求，作为设计、开发、测试与验收的依据。

### 1.2 产品定位

本系统为食用菌基地的**农业监控 / 农场 IoT 管理中枢**，消费既有 IoT / 边缘 AI 已产出的识别结果与环境数据，提供接入治理、告警闭环、采摘台账、报表、设备档案、RBAC，以及可选的基地监控大屏。

看板与大屏的视觉方向：**清亮农作物监控风格**为主（明亮、作物与棚区状态可读）。暗色仅作可选方向，**不是验收硬约束**。本产品是农业监控，**不得**类比或按公安 / 雪亮等公共安全视频监控系统验收（该说法只来自早期头脑风暴，不是产品定位）。

**明确非目标**：本应用**不**建设、不交付计算机视觉算法或边缘推理能力。

### 1.3 读者

产品、研发、测试、甲方业务/IT、边缘对接方、招标评审（可与 `bid-sample` 对照）。

### 1.4 术语

| 术语 | 含义 |
|------|------|
| 边缘 AI 盒 | 棚端完成识别推理的既有设备；本平台只收结果 |
| 识别结果 | 数量、成熟、菌盖直径、病害、抓拍等结构化数据 |
| 棚区 | 栽培管理单元；【假设】共 30 个 |
| 三级告警 | 提示 / 一般 / 严重 |
| 补传 | 断网或失败后的幂等重报 |
| 平面棚图 | 2D/拓扑示意，非真 3D |

## 2. 背景与目标

### 2.1 业务背景

基地已部署约 **110 路**摄像头、配套 AI 盒与环境传感器，具备数菇/成熟/病害/环境采集能力，但缺乏统一汇聚、告警闭环与采摘/报表运营界面，也缺少可投屏的农业监控展示。

### 2.2 建设目标

1. 稳定接入并治理边缘上报数据（校验、去重、补传、可观测拒收）。  
2. 形成可配置的三级告警与处置闭环，降低漏报与噪音。  
3. 支撑当日采摘清单与多类 Excel 报表。  
4. 管理摄像头 / AI 盒 / 传感器档案与在线状态。  
5. 四角色权限、棚隔离与审计。  
6. 交付可投屏的基地监控大屏（平面示意；清亮农作物风格为主，暗色非必须），二期增强分析与 IM 推送。

### 2.3 非目标（Non-goals）

- 不做 CV 训练、模型优化、边缘推理部署。  
- 不做真三维数字孪生。  
- 不做 ERP/财务/电商/人事。  
- 不承诺未冻结协议之外的任意边缘厂商私有协议「即插即用」（需适配）。  
- MVP 不承诺企微/钉钉（二期）。

## 6. 非功能需求

### 6.1 性能【假设】

| 项 | 指标 |
|----|------|
| 接入规模 | 约 110 路，每路 1–5 分钟上报；支持补传突发 |
| API（管理端） | 常规查询 P95 ＜ **2s**（局域网私有化） |
| 大屏刷新 | 汇总指标【假设】≤ **30s** 可配置刷新 |
| 导出 | 单次导出【假设】≤ 5 万行；超限需分页/异步（可二期） |

### 6.2 可用性与可靠性【假设】

| 项 | 指标 |
|----|------|
| 服务可用性 | 私有化目标 **≥ 99%**（月）；依赖甲方供电与网络 |
| 数据不丢 | 已确认入库的识别记录不因服务重启丢失；补传幂等 |
| 故障恢复 | 依赖 docker 重启；RPO/RTO 与甲方备份策略另约 |

### 6.3 数据保留【假设】

| 数据类型 | 保留 |
|----------|------|
| 识别/环境**时序明细** | **90 天**在线 |
| **抓拍**热数据 | **30 天**在线 |
| 日聚合指标 | ≥3 年 |
| 审计日志 | ≥1 年 |
| 告警工单 | ≥1 年 |

### 6.4 安全

- 账号密码登录；会话存 Redis；【假设】密码哈希存储。  
- 敏感操作可二次确认（删设备、改全局阈值等）。  
- 接口鉴权；边缘上报【假设】Token 或 mTLS（联调约定）。  
- 棚隔离强制于服务端。

### 6.5 易用与 UI

- 简体中文；时区 Asia/Shanghai。  
- 看板与大屏为**清亮农作物 / 农业监控风格**。暗色科技风只是可选视觉方向，**不是硬约束**。  
- **禁止**把界面验收写成公安 / 雪亮或公共安全指挥中心风格。  
- 大屏平面示意即可，**禁止**将真 3D 列为验收项。

### 6.6 兼容

- 管理端与大屏：Chrome / Edge 近两个大版本。

## 8. 接口需求（对接 IoT / 边缘方）【假设】样例

> 正式联调以**冻结版**为准；下列为样例形状，便于平行开发。

### 8.1 MQTT Topics【假设】

```
mushroom/{siteId}/shed/{shedId}/camera/{cameraId}/recognition
mushroom/{siteId}/shed/{shedId}/device/{deviceId}/heartbeat
mushroom/{siteId}/shed/{shedId}/env/{sensorId}/telemetry
```

QoS【假设】：识别与补传相关 **QoS 1**。

### 8.2 识别结果 JSON 样例【假设】

```json
{
  "msgId": "aibox-01-20260923T093000Z-0001",
  "siteId": "site-01",
  "shedId": "shed-12",
  "cameraId": "cam-12-03",
  "aiBoxId": "aibox-12",
  "recognizeAt": "2026-09-23T09:30:00+08:00",
  "mushroomCount": 128,
  "matureCount": 36,
  "capDiametersMm": [32.5, 41.0, 28.2],
  "diseaseCount": 2,
  "diseaseLevel": "low",
  "snapshot": {
    "contentType": "image/jpeg",
    "sizeBytes": 245678,
    "sha256": "…",
    "objectKeyHint": "shed-12/2026-09-23/cam-12-03/093000.jpg"
  },
  "env": {
    "temperatureC": 18.2,
    "humidityPct": 86.0,
    "co2Ppm": 980,
    "substrateMoisturePct": 62.5
  }
}
```

### 8.3 HTTP 上报【假设】

- `POST /api/v1/ingest/recognition`  
  Header：`Authorization: Bearer <device-token>`  
  Body：同上 JSON；成功返回 `{ "code": 0, "deduped": false, "recordId": "…" }`  
- `POST /api/v1/ingest/recognition/batch`  
  补传数组；逐条幂等；返回每条成功/去重/失败原因。  
- `POST /api/v1/ingest/heartbeat`  
  设备在线心跳。

### 8.4 错误约定【假设】

| HTTP | 含义 |
|------|------|
| 400 | Schema 失败 |
| 401/403 | 鉴权失败 |
| 409 | 可选：业务冲突 |
| 200 + deduped=true | 重复键，已忽略双计 |

## 9. 告警规则默认值【假设】

环境偏离相对棚档案「设定中心」计算；样本中心见 §3 H13。

| 类型 | 提示 | 一般 | 严重 |
|------|------|------|------|
| 单路成熟占比 | ≥40% | ≥60% | ≥80% |
| 单路病害数量 | ≥1 | ≥3 | ≥5 或高等级病害 |
| 温度偏离设定 | ±1℃ | ±2℃ | ±3℃ |
| 湿度偏离设定 | ±5%RH | ±10% | ±15% |
| CO₂ | 超上限 10% | 20% | 30% |
| 设备离线 | 心跳缺 2 周期 | 缺 5 周期 | 缺 ≥15 分钟 |
| 生长停滞 | — | 连续 48h 直径无增长 | 连续 72h |

可配置项：静默期、同类合并窗口、是否启用某类型（后台）。

## 12. 范围外（Out of Scope）重申
