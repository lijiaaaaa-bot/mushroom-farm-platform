## 1. 项目背景与目标

### 1.1 背景

食用菌基地侧已部署摄像头、边缘 AI 盒与环境传感器，可产出识别结果（数量、成熟度、菌盖直径、病害、抓拍）及环境量（温湿度、CO₂、基质含水率）。当前缺少统一的**管理汇聚中枢**，难以形成「收数 → 告警闭环 → 采摘台账 → 报表」的可运营闭环，也缺少公安/雪亮风格的暗色指挥展示。

### 1.2 建设目标（一句话）

建设**管理汇聚平台**：消费既有 IoT/边缘 AI 的就绪结果，完成数据接入、三级告警闭环、采摘清单与 Excel 报表、设备档案与四角色 RBAC，并交付可演示的暗色管理端与指挥大屏（平面棚图）；**本应用不内建计算机视觉**。

### 1.3 成功标准（摘要）

| 分期 | 成功标准 |
|------|----------|
| MVP | 双通道稳定收数；告警可配可闭环；采摘清单与 ≥2 类 Excel；约 110 路设备可管；四角色+棚隔离+审计可演示；暗色平面大屏可投屏 |
| 二期 | 精装指挥大屏/抓拍墙；生长趋势与病害—环境联动；2–3 日产量预估（标「估计」）；企微/钉钉任选一通道推送 |

## 2. 范围界定

### 2.1 在范围（In Scope）

- MQTT + HTTP 双通道接入：校验、去重、异常过滤、断网补传；抓拍归档（MinIO）。
- 告警：可配规则；提示/一般/严重；确认→处置→关闭/误报闭环；MVP 站内+浏览器通知。
- 采摘当日可采统计与每日清单；生长/病害/环境/设备/告警类 Excel 导出。
- 摄像头（约 110 路）、AI 盒、传感器档案与在线状态。
- **【假设】30 棚**档案与平面示意。
- RBAC：超管 / 生产管理员 / 棚区负责人 / 查看；棚数据隔离；登录与操作审计。
- UI：Vue3 管理端 + 暗色科技农业风指挥大屏（**平面/拓扑示意，不承诺真 3D**）。

### 2.2 不在范围（Out of Scope）

- 计算机视觉模型训练、边缘推理、摄像头/AI 盒硬件采购与部署。
- 真三维数字孪生、GIS 真三维。
- ERP / 财务 / 电商 / 人事考勤。
- 非约定第三方系统深度集成（除二期企微/钉钉推送外）。

### 2.3 分期范围（能力分期，非周历）

| 分期 | 内容 | 交付节奏【假设】 |
|------|------|------------------|
| **MVP（一期）** | 接入、告警闭环、采摘/报表、设备/RBAC、管理端可用、大屏基础总览 | **Day-1 架构地基 → Day-scale 垂直切片 → 可演示 MVP**；日历由 coding agent 加速，**不以 6–8 周为默认工期** |
| **二期** | 精装指挥大屏、生长趋势、病害—环境联动、2–3 日产量预估、企微/钉钉推送 | 在稳定接缝上持续迭代；与 MVP 尾期可重叠打磨 |

> **原则**：架构从 Day-1 地基**向外生长**，功能后落地时不另起炉灶、不堆积结构债。详见 [`架构快速生长原则.md`](./架构快速生长原则.md)。

## 3. 技术基线【假设】

| 层 | 选型 |

## 4. 交付模式与 Day-scale 时间表【假设】

> **起算日**：2026-09-23（周三，CST）。  
> **交付模式**：coding agent 加速；**Day-1 先立全骨架与稳定接缝**，再按日切垂直切片，避免「先堆功能、后补架构」。  
> **废止**：以「约 6–8 周」为 MVP 主工期、以及 W1–W11 周历慢排期。甲方对外招标文档可只写 MVP/二期能力分期，不强制写日历天数。

### 4.1 八行时间表摘要（头条）

```
Day 0–1   全骨架：monorepo、docker 依赖、Nest 模块桩、Vue 壳、
          ingest/alert/RBAC/device/harvest/report 接线、配置、seed、CI 冒烟
Day 1–2   垂直切片：HTTP 接入→落库→列表；告警创建/确认；暗色管理端页面可走

二期       精装大屏 / 趋势联动 / 产量预估 / IM 推送 — 仍挂同一地基向外长
```

### 4.2 Day 0–1：架构地基（必须一次到位）

| 交付 | 完成标志 |
|------|----------|
| Monorepo + 包边界 | apps/api、apps/web、packages/shared（DTO/常量）可本地跑 |
| docker-compose 依赖 | PG / Redis / MinIO / Mosquitto 一键起；健康检查通过 |
| Nest 模块桩已接线 | `Ingest` · `Alert` · `Rbac` · `Device` · `Harvest` · `Report` 模块注册，空路由/空服务可冒烟 |
| Vue 暗色壳 | 布局、路由占位、登录壳、管理端导航骨架 |
| 配置与 seed | 环境变量模板；四角色 + 样例棚/设备/用户 seed |
| 接缝冻结草案 | Ingest DTO、告警状态机、RBAC 角色、MinIO key 布局、MQTT Topic 命名写入仓库 |
| CI-ish 冒烟 | lint/typecheck + compose up + 健康检查脚本可绿 |

> Day-1 结束后：**功能可薄，结构不可缺**。后续功能只往已有模块与接缝里填，不临时开旁路。

### 4.5 Ongoing：接缝上的快速迭代

在 Day-1 冻结的接缝上由 agent / 人协同持续加厚：

- 协议适配器（多厂商报文 → 统一 Ingest DTO）  
- 告警规则与噪音治理（静默期、合并）  
- UI 屏与大屏精装、采摘修正、报表字段  
- 二期：趋势、病害—环境联动、产量预估、企微/钉钉  

**架构从地基向外长，不后期螺栓式硬塞。**

## 6. 风险与缓解

| ID | 风险 | 影响 | 概率【假设】 | 缓解措施（接缝优先） |
|----|------|------|--------------|----------------------|
| R1 | 边缘协议迟迟不冻结 / 频繁变更 | 接入返工 | 中 | **Day-0/1 强制冻结**样例 JSON + Topic；变更走版本号；**协议适配层**隔离，核心 Ingest DTO 不动 |
| R2 | 上报数据质量差 | 告警误报、报表不可信 | 高 | 严格 Schema 接缝；去重键；拒收可观测；补传幂等 — 均在 Day-1 管道内预留 |
| R3 | 告警噪音过大 | 用户弃用闭环 | 中 | **告警状态机与规则接口早冻结**；默认保守；静默/合并可迭代调参 |
| R4 | 抓拍存储与带宽压力 | 磁盘打满、大屏卡顿 | 中 | **MinIO key 布局 Day-1 定死**；【假设】在线 30 天；缩略图与限流后加 |
| R5 | 产量预估历史不足 | 二期预估无法验收 | 中 | 明确「满 30 天有效历史」门槛；未达标演示模拟集 |
| R6 | 真 3D / 过度 UI 期望 | 范围膨胀 | 中 | 书面约定平面示意；对照 `bid-sample/05`；UI 屏在壳内迭代不改导航契约 |
| R7 | 功能堆叠导致结构债 | 后期难改、迭代变慢 | 中 | **禁止旁路模块**；新能力只进既有 seam；Day-1 模块桩不可缺席 |
| R8 | 私有化环境网络/证书问题 | 部署延期 | 低 | 提前 docker-compose 清单；甲方 IT 提前开端口 |
| R9 | Agent 产出偏离接缝 | 隐式双实现 | 中 | PR/冒烟卡契约测试；共享 DTO 包为唯一真相源 |

## 8. 验收大纲

### 8.1 MVP 验收包

1. **接入**：按冻结样例连续接收（【假设】联调 ≥24h 可观察）；非法报文拒收可查；补传不双计；抓拍可按棚/日/摄像头打开。  
2. **告警**：触发至少 3 类（如成熟、病害、环境或离线）；完成确认→处置→关闭/误报；审计可检索。  
3. **采摘与报表**：生成当日采摘清单；导出至少 2 类 Excel 且字段与筛选一致。  
4. **设备与权限**：约 110 路级档案可维护；四角色菜单/API 双控；跨棚数据隔离演示通过。  
5. **大屏**：暗色基础指挥页可 1920×1080 投屏；平面棚图可下钻摘要；**不验收真 3D**。

### 8.2 二期验收包

1. 精装大屏/抓拍墙按演示脚本走通。  
2. 生长趋势（7/30 天）与病害—环境同屏对照可复盘。  
3. 2–3 日产量预估标注「估计」；【假设】满 30 天有效历史后开启正式预估验收。  
4. 企微或钉钉任选一通道推送严重告警成功。

### 8.3 验收方式【假设】

- 现场或远程演示 + 勾选表签字。  
- 缺陷分级：致命/严重须关闭或有书面豁免；一般可列入保修。  
- 【假设】验收后 12 个月缺陷修复（商务可调，本计划书不报价）。
